# Step 2.6：account repository

## 目標與結果
`account.Repository.Create(ctx, *Account)` 能把帳號寫進 `accounts` 表，並在 `a.UUID` 填入新產生的 UUID。
工號重複時回傳 `ErrEmployeeIDTaken`，呼叫者不需要認識 MySQL 的錯誤碼。
整合測試覆蓋成功與重複兩種情況，`make test` 通過，後端覆蓋率 90.0%（門檻 80%）。
對應專案不變量「SQL 一律參數化」「能交給資料庫約束的，就交給資料庫」。

## 學到的概念

**repository 層的職責**：只管「怎麼存、怎麼取」，不驗證輸入，不知道 HTTP。
Spring 對應 `@Repository` / `JdbcTemplate`。Go 沒有框架，所以是一個包著 `*sql.DB` 的 struct。

**手動接線**：`NewRepository(db)` 是手寫的 constructor。
Spring 的 `@Autowired` 會自動注入 `DataSource`，Go 要自己傳進去。多寫的幾行是刻意的明確性，不是遺漏。

**參數化 SQL**：用 `?` 佔位，值另外傳給驅動。資料和指令分開送，資料裡的 SQL 片段只是一串字。
```go
r.db.ExecContext(ctx,
    `INSERT INTO accounts (uuid, employee_id, name, password_hash) VALUES (?, ?, ?, ?)`,
    a.UUID.String(), a.EmployeeID, a.Name, a.PasswordHash,
)
```

**辨識 error 1062**：MariaDB 的 UNIQUE 衝突編號是 1062。
Spring 會自動翻成 `DuplicateKeyException`，Go 要自己用 `errors.As` 取出 `*mysql.MySQLError` 再比對。
```go
var me *mysql.MySQLError
if errors.As(err, &me) && me.Number == 1062 &&
    strings.Contains(me.Message, "uq_accounts_employee_id") {
    return ErrEmployeeIDTaken
}
```
`uuid` 欄位也是 UNIQUE，所以要多比對訊息裡的 key 名稱，才能確定衝突的是工號。
這代表 migration 裡的 `uq_accounts_employee_id` 名稱不能隨便改。

**哨兵錯誤（sentinel error）**：`var ErrEmployeeIDTaken = errors.New(...)`。
Go 沒有 exception，錯誤是回傳值，呼叫者用 `errors.Is` 比對。

**UUID 在 Go 產生**：用 `google/uuid`。`uuid` 欄位沒有 default，而且 `Create` 需要把 UUID 帶回給呼叫者。
`google/uuid` 原本就是 `go.mod` 的間接依賴，這一步只是改成直接依賴（`go get`），沒有引入新套件。

**不要先 SELECT 再 INSERT**：兩個請求可能同時通過檢查，再都 INSERT，產生競態（race condition）。
交給 DB 的 UNIQUE 約束，由資料庫保證，應用程式只負責把錯誤翻譯。

**`%w` 包裝錯誤**：`fmt.Errorf("insert account: %w", err)` 加上情境，同時保留原錯誤，上層仍可 `errors.Is` / `errors.As`。

**`TestMain` 與 `os.Exit`**：`os.Exit` 不會執行 defer，所以要先明確呼叫 `stop()` 關掉容器，再 `os.Exit(code)`。
整個 package 只啟動一次容器，每個測試開頭用 `dbtest.Reset` 清資料，測試順序不影響結果。

## 自我檢查
1. 拿掉 `strings.Contains(me.Message, "uq_accounts_employee_id")`，只留 `Number == 1062`，風險是什麼？
   答：隨機產生的 `uuid` 剛好撞到時，也會被誤報成「工號已被使用」。（C）
2. 為什麼不先 `SELECT` 檢查工號，再 `INSERT`？
   答：兩個請求可能同時通過 `SELECT`，再都 `INSERT`；沒有 DB 的 UNIQUE 就會寫入重複資料。（C）
3. 為什麼用 `%w` 而不是 `%v`？
   答：`%w` 保留原錯誤，上層仍可用 `errors.Is` / `errors.As` 判斷。（D）

# 4.3 frontend image

## 目標與結果

把前端 build 出來的靜態檔和 Nginx 打包成 image，Nginx 同時負責把 `/api` 轉給後端（同源）。

驗收：經 Nginx 打 `/api/health`，回 `200` 和 `{"status":"ok"}`。實際輸出帶有後端產生的 `X-Request-Id`，表示請求確實轉到後端。

新增檔案（都在 `frontend/`）：

- `Dockerfile`：兩階段。build 階段用 `node:24-alpine` 跑 `npm ci` 和 `npm run build`；runtime 階段用 `nginxinc/nginx-unprivileged:1.29-alpine`，只帶 `dist/` 和設定檔。
- `nginx.conf`：`/api/` 轉給後端、`/assets/` 長期快取、其他路徑 SPA fallback。
- `.dockerignore`：排除 `node_modules`、`dist`、`.env*`。

```bash
docker build -t esg-frontend:dev frontend
docker run --rm -p 8081:8080 esg-frontend:dev
curl -i http://localhost:8081/api/health
```

## 學到的概念

- **為什麼需要 Nginx**：`dist/` 只是一堆檔案，容器裡要有一個行程監聽 port、設 `Content-Type`、處理快取和 SPA fallback。Nginx 是靜態檔伺服器。Spring 類比：Spring Boot 內嵌 Tomcat 一包搞定；這裡「伺服靜態檔」和「API」是兩個行程，路由規則要自己寫。
- **同源與反向代理**：同源指 scheme、host、port 都相同。要讓瀏覽器只看到一個入口，就需要某個東西依路徑分流（`/` 給前端、`/api` 給後端）。compose 時由 Nginx 做；k8s 的 Ingress 也能做同樣的事（4.9）。同源所以不需要 CORS。
- **SPA fallback**：`/login` 不是真實檔案，重新整理時 Nginx 找不到會回 404。`try_files $uri /index.html` 讓它「找不到就回 `index.html`」，交給 React Router。
- **`proxy_pass` 不帶路徑**：`proxy_pass http://host:8080;` 會把 `/api/health` 原樣轉出去。若結尾加了路徑（例如 `/`），`/api/` 前綴會被吃掉。
- **快取策略**：Vite 輸出的檔名帶內容 hash，所以 `/assets/` 可以 `immutable` 快取一年；`index.html` 要 `no-cache`，否則瀏覽器會拿舊 HTML 去找已不存在的舊 hash 檔。
- **envsubst template**：放進 `/etc/nginx/templates/*.template` 的檔案，在容器啟動時會用環境變數替換 `${VAR}`，再寫到 `/etc/nginx/conf.d/`。只替換「已定義的環境變數」，所以 `$uri`、`$host` 不受影響。類比 `application.yaml` 的 `${DB_URL}`。
- **`nginx-unprivileged`**：非 root 執行，所以監聽 8080（非 root 不能綁 1024 以下）。跟 backend 的 `distroless:nonroot` 一致。
- **`proxy_pass` 在啟動時解析位址**：後端不存在時，Nginx 會起不來（`host not found in upstream`）。4.4 的 compose 會碰到啟動順序。

```nginx
location /api/ { proxy_pass ${BACKEND_URL}; }
location /     { try_files $uri /index.html; }
```

## 問題與解答

**同源了還需要反向代理 `/api` 嗎？**
需要某個東西做路徑分流，不一定是 Nginx。compose 沒有 Ingress，所以 Nginx 要代理；k8s 的 Ingress 可以直接按路徑分流，到 4.9 時 `/api/` 區塊可以拿掉。另一條路是讓後端自己伺服 `dist/`（Go `embed`），就完全不用代理，但 ROADMAP 沒選這條。

**為什麼不能只把 `dist/` 放進 image？**
沒有任何行程處理 HTTP 請求。需要一個靜態檔伺服器處理 MIME type、快取、SPA fallback、壓縮。Nginx 只是常見選擇，Caddy 或 Go `embed` 也可以。

**哪些設定不用額外設定、哪些建議設定？**
預設就夠用：`mime.types`、`ETag` 和 `Last-Modified`、`sendfile`、`keepalive`、proxy timeout 60 秒。
建議設定（這一步先不加）：

| 項目 | 原因 |
|---|---|
| `gzip on` + `gzip_types` | 官方 image 預設是註解掉的，JS、CSS、JSON、SVG 可壓到約 1/3 |
| `server_tokens off` | 預設會在 `Server` header 暴露 Nginx 版本 |
| `X-Content-Type-Options: nosniff` | 防止瀏覽器猜 MIME type |
| `Referrer-Policy` | 減少網址外洩 |
| `X-Frame-Options: DENY` 或 CSP `frame-ancestors` | 防 clickjacking |
| CSP | 最強的 XSS 防線，排在 M10 |
| HSTS | 只在 HTTPS 才設；TLS 在 Ingress 終結，HTTP 的 Nginx 不要設 |

陷阱：Nginx 的 `add_header` 只要在某個 `location` 內出現，就不會繼承 `server` 層的 `add_header`。我們的 `/assets/` 和 `/` 都用了 `add_header Cache-Control`，之後加安全 header 時每個 location 都要重複，或用 `include` 共用檔。

**`curl /api/login` 回 `404 page not found`，是 Nginx 的 404 嗎？**
不是。`Content-Type: text/plain` 加上 `X-Request-Id` 是 Go 後端的 404。這表示 `/api/` 有被轉給後端，沒有落到 SPA fallback。

## 自我檢查

1. 刪掉 `try_files $uri /index.html;`，使用者在 `/login` 按重新整理會看到什麼？
   答：Nginx 回 404。它到 `root` 底下找 `/login` 這個檔案，找不到就回 Not Found；`index.html` 只在請求 `/` 時才會被當預設頁面。
2. 把 `nginx.conf` 複製到 `/etc/nginx/conf.d/default.conf`（不是 `templates/`），容器啟動會怎樣？
   答：啟動失敗。沒有經過 `envsubst`，Nginx 自己解析 `${BACKEND_URL}`，把它當成內建變數，但這個變數不存在，設定檢查階段就失敗。

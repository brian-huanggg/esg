# Step 2.1：用 compose 啟動 MariaDB

## 目標與結果
`make db-up` 起一個 MariaDB 容器，`docker compose ps` 顯示 healthy，用 client 執行 `SELECT 1` 回 1。
- 新增 `deploy/compose.yaml`、`.env.example`，Makefile 加 `db-up` / `db-down`
- 映像檔用 `mariadb:11.4`（LTS，支援原生 `UUID` 型別）。原本 ROADMAP 決定 10.11，學習者自行改成 11.4

## 學到的概念
- **docker compose**：用 YAML 描述容器，取代一長串 `docker run`。
- **volume**：容器刪掉檔案就沒了；資料目錄掛 volume（`db-data:/var/lib/mysql`），`down` 後資料還在，`down -v` 才會刪。
- **healthcheck**：「在跑」不等於「能用」。`healthcheck.sh --connect --innodb_initialized` 確認能連線且 InnoDB 初始化完成。
- **`up -d --wait`**：`-d` 只等容器啟動；`--wait` 等到 healthy，失敗時回非 0，讓 `make` 和 CI 能擋住後續步驟。
- **`.env` / `.env.example`**：`.env` 放真值（gitignored），`.env.example` 放假值（進 git）。
- **`MARIADB_*` 變數只在資料目錄第一次建立時生效**；之後改 `.env` 不會改到已存在的使用者密碼。

```yaml
ports:
  - "127.0.0.1:3306:3306"   # host-ip:host-port:container-port
```

## 問題與解答
- **`--wait` 差在哪？** `up -d` 容器一啟動就回來，DB 還在初始化時下一個指令會 `connection refused`；`--wait` 等到 healthy。
- **CMD 和 ENTRYPOINT？** ENTRYPOINT 是固定執行的程式，CMD 是預設參數，實際執行 ENTRYPOINT + CMD。`docker run image xxx` 只換 CMD。mariadb：ENTRYPOINT `docker-entrypoint.sh`（做初始化），CMD `mariadbd`。`healthcheck.test` 裡的 `"CMD"` 意思不同：直接執行、不經 shell（另一種是 `CMD-SHELL`）。
- **`test: [...]` 在做什麼？** 見上方 healthcheck；exit 0 成功，連續失敗 10 次（每 5 秒）才標 unhealthy。
- **`down` 有 graceful period 嗎？** 有：`SIGTERM`，等 10 秒（`-t` 或 `stop_grace_period` 可調），再 `SIGKILL`。與 k8s 機制相同，但沒有 `preStop` hook 和 endpoint 摘除。DB 收到 SIGTERM 才能把緩衝區寫回磁碟。
- **資料目錄一律 `/var/lib/mysql` 嗎？** 不是，是各映像檔的預設 datadir。MySQL/MariaDB：`/var/lib/mysql`；Postgres：`/var/lib/postgresql/data`（`PGDATA`），Postgres 18 起映像檔改掛 `/var/lib/postgresql`。用 <span v-pre>`docker image inspect <image> --format '{{json .Config.Volumes}}'`</span> 確認。

## 除錯記錄
1. **`no such file or directory`**：檔名是 `compose.yaml`，Makefile 寫 `compose.yaml`。檔名和引用處要一致。
2. **`The "HScG" variable is not set`**：`.env` 的值含 `$`，compose 會當變數代入。
3. **`ERROR 1045 Access denied`**：密碼含單引號 `'`，`.env` 解析與 shell 取值各自解讀；加上 `MARIADB_PASSWORD` 只在第一次初始化生效，要 `down -v` 清 volume 才會重新套用。
   修法：用 `openssl rand -hex 16` 產生只含英數字的密碼。

## 自我檢查
1. `db-down` 再 `db-up`，資料還在嗎？—— 在，volume 保留了資料目錄。
2. `down -v` 會怎樣？—— 連 volume 一起刪，資料消失。
3. port 為什麼寫 `127.0.0.1:3306:3306`？—— 不寫會綁在 `0.0.0.0`，host 的每張網卡（含 LAN）都能連到 DB；寫了只有本機能連。

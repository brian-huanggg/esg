# Step 2.4：testcontainers，整合測試底座

## 目標與結果
測試自己啟動真的 MariaDB 11.4 容器、套用 `backend/migrations` 的 up、提供 `Reset` 讓每個測試從空表開始。
`TestAccounts_EmployeeIDUnique` 證明重複工號會得到 MySQL error 1062。
`make test` 通過，後端覆蓋率 90.0%（門檻 80%，`dbtest/` 已排除在計算之外）。

## 學到的概念

**testcontainers-go**：在測試程式裡用 Docker API 啟動容器，測完自動銷毀（`testcontainers/ryuk` 容器負責在程式當掉時清理）。
Spring 對應 `@Testcontainers` + `@Container` + `@DynamicPropertySource`；Go 要自己取連線字串、自己套 migration。

**`TestMain`：每個 package 只啟動一次容器**
```go
func TestMain(m *testing.M) {
    db, stop, err := Start(context.Background())
    if err != nil { fmt.Fprintln(os.Stderr, err); os.Exit(1) }
    testDB = db
    code := m.Run() // runs every Test* in this package
    stop()          // must run before os.Exit, which skips defers
    os.Exit(code)
}
```
容器啟動約 5 秒，是測試的瓶頸，所以整個 package 共用一個。只有呼叫 `Start` 的 package 才會碰 Docker。

**為什麼不 mock DB**：UNIQUE、CHECK、`UTC_TIMESTAMP` 都是 DB 的行為，mock 只會回預先寫好的答案。

**資料隔離：共用容器加每個測試前 `TRUNCATE`**
- 每測試一個容器：太慢。
- transaction 回滾：repository 自己會 `Begin`/`Commit`，包不住。
- 共用容器加 `TRUNCATE`：快，夠乾淨。

**`SET FOREIGN_KEY_CHECKS` 是 session 層級**，`*sql.DB` 是連線池，所以 `Reset` 要用 `db.Conn(ctx)` 固定同一條連線，否則 `SET` 與 `TRUNCATE` 可能落在不同連線，結果時好時壞（flaky）。

**取得 DSN**：容器 port 隨機，用 `ctr.ConnectionString(ctx)`；`sql.Open` 加 `?parseTime=true`，golang-migrate 前面加 `mysql://`。

**錯誤處理**
```go
var me *mysql.MySQLError
if !errors.As(err, &me) || me.Number != 1062 { ... }
```
`errors.As` 沿錯誤鏈找特定型別；`||` 短路避免 nil 取值；要比對 1062，不能只檢查 `err != nil`，否則任何錯誤都會讓測試通過。
`fmt.Errorf("...: %w", err)` 的 `%w` 要傳 `err` 本身，不是 `&err`。

**其他語法**
- 首字母大寫就是 exported（`Start`、`Reset`），小寫只有同 package 看得到。
- `_ "pkg"` blank import：只為了執行 `init()` 註冊 driver。
- `runtime.Caller(0)`：取得原始檔位置，讓任何 package 的測試都找得到 `backend/migrations`。
- `t.Helper()`：失敗行號指向呼叫者。

**Migration 政策**：業界正式環境 forward-only（出問題再寫新的 up 往前修），down 只在開發環境用。本專案保留 up+down，部署到 k3s 之後不執行 down。
部署時 migration 建議用 ArgoCD PreSync hook Job（M11 再做），不是 init container（每個 Pod 都會跑）。

**testcontainers 在 k3s 不會執行**：它只在 `go test` 時跑（筆電、CI）；`dbtest` 只被 `_test.go` 引用，不會編進 binary。

**覆蓋率排除**：`dbtest/` 是測試基礎設施，不是產品程式碼，錯誤分支又得弄壞 Docker 才能觸發，所以在 Makefile 的 `sed` 加 `-e '/shared\/dbtest\//d'`，與 `.gen.go`、`main.go` 的處理一致。

## 學習者的提問與解答
- 為什麼 `Reset` 要大寫？Go 用首字母大小寫決定可見性。
- `dbtest` 是單元測試嗎？不是，是整合測試。若之後整合測試變多、本機太慢，可用 `//go:build integration` build tag 分離（目前不做）。
- Spring 自動處理這些事比較好嗎？各有取捨：Spring 省樣板但魔法難追，Go 明確但程式碼多。這個專案手動接線是為了看見框架背後做了什麼。

## 自我檢查
1. `Reset` 不用 `db.Conn` 會怎樣？目前一張表測試會過；有 FK 後 `TRUNCATE` 會失敗。原因是 `SET FOREIGN_KEY_CHECKS` 只對一條連線有效，連線池可能把後續語句送到別的連線，而且重用同一條連線時會剛好成功，造成 flaky。
2. `Start` 放進每個測試？結果不變，但每個測試多約 5 秒、浪費 CPU 與記憶體。

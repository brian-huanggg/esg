# Step 2.8a：讀回 DB 的 created_at，修正密碼長度規格

## 目標與結果
`Repository.Create` 在 INSERT 後，用 uuid 查回 `created_at`，填進 `Account.CreatedAt`。
spec 的 `password.maxLength` 從 75 改成 72，與 service 的 bcrypt 上限一致。
`make test` 通過，後端覆蓋率 89.4%（門檻 80%）。為 2.8b 的 201 回應（需要 `createdAt`）做準備。

## 學到的概念

**唯一的時鐘是 DB**：`created_at` 由 migration 的 `DEFAULT UTC_TIMESTAMP(3)` 產生，應用程式不用 `time.Now()`。
所以 INSERT 後要自己讀回來。Spring 的 JPA `save()` 會自動回填，Go 沒有 ORM，要手動 `Scan`。
```go
err = r.db.QueryRowContext(ctx,
    `SELECT created_at FROM accounts WHERE uuid = ?`, a.UUID.String(),
).Scan(&a.CreatedAt)
```

**用 uuid 查而不是 `LastInsertId`**：對外用 UUID 是專案不變量，且 `uuid` 有 UNIQUE 索引。

**`parseTime=true`**：DSN 少了它，驅動把 `DATETIME` 當 `[]byte` 回傳，`Scan` 進 `*time.Time` 會回傳 error，
`Create` 會包成 `read back created_at: ...`。專案的 DSN 已有這個參數。

**規格先行**：spec 與實作不一致時，先改 `api/openapi.yaml`，再 `make gen`。

## 自我檢查
1. 為什麼 INSERT 之後要再 SELECT `created_at`，而不是用 `time.Now()`？
   答：專案規定唯一的時鐘是 DB（UTC），避免多台機器時鐘不同步。
2. DSN 沒有 `parseTime=true` 時，`Scan(&a.CreatedAt)` 會怎樣？
   答：`Scan` 回傳 error（`[]byte` 無法轉成 `*time.Time`）。
   學習者曾誤選「回傳零值」和「自動用本地時區」：驅動在這個開關關閉時不會解析，也不會靜默給零值。

# 5.2 規格：建立與取得提案（501 stub）

## 目標與結果

先在 `api/openapi.yaml` 定義 `POST /api/proposals` 和 `GET /api/proposals/{id}`，再用 501 stub 讓後端能編譯。

- `api/openapi.yaml`：新增兩個 path、`CreateProposalRequest` / `Proposal` schema、共用的 `ETag` header、`NotFound` response
- `backend/internal/proposal/handler.go`：`ProposalHandler` 的兩個方法都回 501
- `backend/cmd/api/main.go`：在 `server` 嵌入 `*proposal.ProposalHandler`，並在 auth map 登記兩個 operation
- `make gen` 產生 `CreateProposal201ResponseHeaders{ETag, Location}` 等型別
- `make test` 通過，proposal 覆蓋率 100%，後端總覆蓋率 90.8%

## 學到的概念

### 1. 回應標頭寫進規格，strict 模式會強制你填

```yaml
"201":
  headers:
    ETag:
      $ref: "#/components/headers/ETag"
    Location:
      required: true
      schema:
        type: string
```

產生的程式碼：

```go
type CreateProposal201ResponseHeaders struct {
	ETag     string
	Location string
}
```

5.4 回 201 時必須填這兩個欄位。標頭也在合約裡，不是 handler 自己想加就加的東西。

ETag 的值要帶引號，例如 `"3"`（RFC 9110 的 strong validator）。5.9 的 `If-Match` 會原樣送回這個值。

### 2. Path 層級的參數

```yaml
/api/proposals/{id}:
  parameters:
    - name: id
      in: path
      schema: { type: string, format: uuid }
  get: ...
```

`parameters` 寫在 path 層級，之後的 PUT / DELETE 都可以共用。`format: uuid` 讓 Go 端拿到 `openapi_types.UUID`，格式錯的 id 在進 handler 之前就被擋下。

### 3. 用 `default` 回 501

strict 模式只替規格裡宣告的狀態碼產生型別。`default` 是唯一可以自己指定狀態碼的出口：

```go
return api.GetProposaldefaultJSONResponse{StatusCode: http.StatusNotImplemented, Body: ...}, nil
```

501 是暫時的，不寫進對外合約。

### 4. 嵌入欄位撞名

Go 的嵌入欄位以「型別名稱」當欄位名，不包含 package 名稱：

```go
type server struct {
	*account.Handler
	*proposal.Handler // compile error: Handler redeclared
}
```

所以改名為 `proposal.ProposalHandler`，跟 `auth.SessionHandler`、`shared.HealthHandler` 同一套命名。

### 5. Go 手動接線：登記需要登入的 operation

```go
authMW := middleware.Authenticate(sessionRepo, logger, map[string]bool{
	"CreateProposal": true,
	"GetProposal":    true,
})
```

Spring Security 用 `.requestMatchers(...).authenticated()` 宣告。Go 這裡要自己把 operation id 放進 map。規格裡的 `security: cookieAuth` 只是文件，不會自動執行檢查。

## 自我檢查

**Q1：如果 auth map 漏寫 `"GetProposal": true`，未登入的人打 GET 會怎樣（stub 階段）？**

答：回 501。map 查不到 key 時回零值 `false`，middleware 就當成公開 API 放行。編譯器和 `make gen` 都不會發現。換成真實作之後，這就是一個沒有驗證的漏洞。

（第一次選了「編譯失敗」。map 是執行時才查的資料，編譯器不知道裡面應該有哪些 key。）

**Q2：stub 為什麼用 `default` 回 501，而不是在規格裡宣告 `"501"`？**

答：501 是暫時的實作細節。strict 模式的 `default` 可以自訂狀態碼，所以不必把它寫進對外合約。

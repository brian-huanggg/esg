# 3.6a 認證 middleware

## 目標與結果

受保護的 operation 沒帶有效 Cookie 時回 401；有效時，`accountID` 和 token 雜湊放進 context。
目前只有 `GetCurrentAccount` 受保護。`/me` 的實作拆到 3.6b，所以有效 Cookie 打 `/me` 暫時回 501（stub），代表 middleware 已放行。

驗收（curl）：

- 沒 Cookie → 401
- 假 Cookie → 401
- 有效 Cookie → 501（stub）

檔案：

- `backend/internal/shared/middleware/auth.go`：`Authenticate`、`AccountIDFrom`、`TokenHashFrom`、`SessionCookieName`
- `backend/internal/shared/middleware/auth_test.go`：fake `sessionFinder`，測拒絕、放行、公開路由
- `backend/internal/auth/handler.go`：`cookieName` 改引用 `middleware.SessionCookieName`
- `backend/cmd/api/main.go`：手動建立 middleware，傳進 `NewStrictHandler`

## 學到的概念

### Context value

Go 沒有 ThreadLocal，所以沿著 `ctx` 參數明確往下傳。Spring 對應 `SecurityContextHolder`。

```go
type accountIDKey struct{}

ctx = context.WithValue(ctx, accountIDKey{}, accountID)
id, ok := ctx.Value(accountIDKey{}).(int64)
```

key 用自訂的 unexported 型別，不同 package 就不可能撞 key；用字串 `"accountID"` 就沒有這層保護。

### Strict middleware 與 operationID

```go
type StrictMiddlewareFunc func(f StrictHandlerFunc, operationID string) StrictHandlerFunc
```

外層函式在**啟動時**對每個 operation 呼叫一次，所以 `if !protected[operationID] { return next }` 只跑一次，公開路由完全沒有額外成本。回傳的內層函式才是每個請求都會跑的。Spring 對應 `SecurityFilterChain` 的 `requestMatchers(...)`。

自己寫好 401 回應後 `return nil, nil`，生成碼看到 response 和 err 都是 nil 就不會再寫一次。

### import cycle

`auth` import `middleware`（用 `RequestIDFrom`），所以 `middleware` 不能 import `auth`。Cookie 名稱因此放在 `middleware.SessionCookieName`，`auth` 去引用。Go 禁止循環依賴，Spring 沒有這個限制。

### Go 要手動接線的地方

`main.go` 要自己建 `authMW`、自己維護受保護清單、自己傳進 `NewStrictHandler`。Spring 靠 filter chain 自動掃描。風險：新增受保護路由卻忘了加進 map，它就變成公開的。

### 驗證流程

1. 讀 Cookie `session`，沒有 → 401
2. 對 Cookie 值字串做 SHA-256（DB 只存雜湊）
3. `FindActive`：未知、閒置逾時、絕對逾時都回 `ErrNotFound` → 401，呼叫端分不出差別
4. 其他錯誤 → 寫 log，回 500，不洩漏原因
5. `Touch` 失敗只寫 log，不擋請求
6. 放進 context，呼叫下一層

## 我問的問題

**Postman 怎麼帶 Cookie？** 登入後 Postman 的 cookie jar 會存 `Set-Cookie`，同 domain 自動帶。但我們的 Cookie 有 `Secure`，用 `http://` 時可能不會回送，最穩的是手動在 Headers 加 `Cookie: session=<token>`。Authorization 分頁沒用，middleware 只讀 Cookie。

## 遇到的問題

- `main.go` 把 `mux` 誤刪，`authMW`（型別是 `api.StrictMiddlewareFunc`）被當成 mux 用，編譯失敗。`authMW` 只傳進 `NewStrictHandler` 的 slice，路由仍由 `mux` 負責。
- 第一次 `make test` 覆蓋率 75.5%，低於 80%，因為 `auth.go` 沒有測試。補測試後 middleware 套件 94.1%，總計 90.6%。

## 自我檢查

1. `if !protected[operationID] { return next }` 什麼時候執行？
   **啟動時，每個 operation 一次。**
2. context key 從 `accountIDKey struct{}` 改成字串 `"accountID"`，最可能出什麼問題？
   **其他 package 用同樣字串當 key 會互相覆蓋或誤讀。** `go vet` 會警告，但不會編譯失敗。

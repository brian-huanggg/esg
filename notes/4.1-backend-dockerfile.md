# 4.1 後端 Dockerfile

## 目標與結果

用 multi-stage build 做出小型後端 image。`docker run` 之後 `curl localhost:8080/api/health` 回 200。

結果：image 約 16.5MB（壓縮內容 3.5MB），使用者為 uid 65532（非 root），image 內沒有 shell。

## 學到的概念

### 多階段建置（multi-stage build）

第一階段用完整 Go 工具鏈編譯，第二階段只複製執行檔。編譯器和原始碼不會進最終 image。

```dockerfile
FROM golang:1.26 AS build
COPY go.mod go.sum ./
RUN go mod download
COPY . .
RUN CGO_ENABLED=0 go build -trimpath -ldflags="-s -w" -o /out/api ./cmd/api

FROM gcr.io/distroless/static-debian12:nonroot
COPY --from=build /out/api /api
ENTRYPOINT ["/api"]
```

### 層快取（layer cache）

先複製 `go.mod`、`go.sum` 再下載依賴。依賴沒變時，這一層直接重用快取，改程式碼不用重下載。

### distroless nonroot

沒有 shell 和 package manager，預設用非 root 使用者執行。攻擊面小，但也不能 `docker exec` 進去。

### `.dockerignore`

決定哪些檔案進 build context。`.gitignore` 和它是兩套獨立機制，`.env` 在 `.gitignore` 不代表 Docker 會跳過。

## 問題與解答

**為什麼用 `ENTRYPOINT` 而不是 `CMD`？**
`ENTRYPOINT` 表示「這個容器就是這個程式」，執行時傳入的參數會接在後面。`CMD` 是預設指令，容易被整個取代。後端是服務，不是工具，所以用 `ENTRYPOINT`。兩者都要用 JSON 陣列（exec form），distroless 沒有 shell。

**為什麼 `CGO_ENABLED=0`？**
CGO 開啟時，標準庫某些部分（例如 `net` 的 DNS 解析）會動態連結 glibc。`distroless/static` 沒有 glibc，啟動會報誤導的 `no such file or directory`。關閉後得到靜態執行檔。`go-sql-driver/mysql` 是純 Go，不需要 CGO。

## 自我檢查

1. 拿掉 `COPY go.mod go.sum` 與 `go mod download`，只留 `COPY . .`，會怎樣？
   答：每次改程式碼都重下載依賴，因為任何檔案變動都讓該層快取失效。
2. 移除 `.dockerignore` 的 `.env`，且 `.env` 在 `backend/` 時？
   答：`.env` 會被 `COPY . .` 帶進 build 階段。最終 image 只複製 `/out/api`，所以不會帶出去，但 build 階段的層仍有外洩風險。

## 驗證指令

```bash
docker build -t esg-backend:dev backend
docker run --rm -p 8080:8080 -e DB_HOST=host.docker.internal \
  -e DB_NAME -e DB_USER -e DB_PASSWORD esg-backend:dev
curl -i localhost:8080/api/health
docker image inspect esg-backend:dev --format '{{.Config.User}} {{.Config.Entrypoint}}'
```

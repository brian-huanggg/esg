# 4.10 platform-gitops：註冊 esg-backend Application

## 目標與結果

在 platform-gitops 新增 `registry/esg-backend.yaml`，並把 backend / migrate / frontend 三個 image 的 tag 填成 `8d85f2c`。
push 後 `root` 自動建立 `esg-backend`：

- `esg-backend`、`esg-frontend` 都是 Synced / Healthy，四個 Pod 都是 Running
- 叢集 DB 有 `accounts`、`schema_migrations`、`sessions` 三張表
- **檢查點 2**：瀏覽器用 HTTPS 註冊、登入成功

這一步只改 platform-gitops，ESG repo 沒有程式碼變更。

## 概念

### app-of-apps

```text
git push (platform-gitops)
  -> root 發現 registry/ 多一個檔案 -> 建立 Application esg-backend
  -> esg-backend 讀 apps/esg/backend + values-dev.yaml -> helm template
  -> PreSync：migrate Job（等 DB -> 跑 migration）
  -> Deployment、Service
```

`registry/*.yaml` 像一份服務註冊表：新增一個檔案就是登記一個 app，不用手動 `kubectl apply`。

```yaml
# registry/esg-backend.yaml（節錄）
metadata:
  annotations: {argocd.argoproj.io/sync-wave: "4"}   # 晚於 esg-secrets (wave 3)
spec:
  source:
    path: apps/esg/backend
    helm: {valueFiles: [values-dev.yaml]}
  syncPolicy:
    automated: {prune: true, selfHeal: true}         # Git 是唯一真相
```

### PreSync hook

migrate Job 帶 `argocd.argoproj.io/hook: PreSync`，在 Deployment 套用之前執行。
`hook-delete-policy: HookSucceeded` 讓成功的 Job 被刪掉，所以事後看不到 Job，要直接查表驗證。

### image tag 來自 Git

tag 是 `make push` 印出的 git SHA。chart 用 `required`，tag 空字串時 `helm template` 失敗，
ArgoCD 顯示 `SYNC STATUS = Unknown`，條件訊息是 `image.tag is required (git SHA)`。

## 這一步的問題與解答

**Q：`esg-frontend` 是 `Unknown`、`esg-backend` 不存在，為什麼？**
ArgoCD 還在用舊 commit（tag 還是空字串）。預設每 3 分鐘輪詢 Git，
可用 `kubectl -n argocd annotate app root argocd.argoproj.io/refresh=hard --overwrite` 手動刷新。
診斷指令：`kubectl -n argocd get app esg-frontend -o jsonpath='{.status.conditions}'`。

**Q：`make db-exec` 能查叢集的 DB 嗎？**
不能。它是 `docker compose exec db`，連的是本機 container。叢集 DB 要用 `kubectl exec` 進 MariaDB Pod。

## 自我檢查

1. migrate Job 的 hook 從 PreSync 改成 PostSync，第一次部署會怎樣？
   答：backend 可能先啟動，而資料表還沒建立。PreSync 保證 schema 先於新 Pod 就緒。
2. `values-dev.yaml` 的 tag 改成 Harbor 上不存在的 SHA 並 push，會看到什麼？
   答：app 顯示 Synced，但新 Pod 卡在 `ImagePullBackOff`。ArgoCD 只比對 Git 與叢集，不會去問 Harbor；
   manifest 合法，問題出在 kubelet 拉 image 的階段。

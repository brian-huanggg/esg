## 學到的概念

### 參數化查詢（防 SQL Injection）

```go
r.db.QueryRowContext(ctx, `... WHERE id = ?`, id)
```

SQL 骨架和值分開送：driver 先 prepare（DB 解析並固定語法結構），再用二進位協定送參數值。值只會填進 `?`，不會再經過 SQL 解析器，所以輸入 `x' OR '1'='1` 只是一串普通字元。Spring 對應 `PreparedStatement` / `JdbcTemplate`。

限制：佔位符只能代表**值**，不能代表表名、欄位名、`ORDER BY` 方向。這類要用白名單：

```go
allowed := map[string]string{"name": "name", "created": "created_at"}
col, ok := allowed[input]
```

### `sql.ErrNoRows` 轉成領域錯誤

```go
if errors.Is(err, sql.ErrNoRows) {
	return nil, ErrNotFound
}
```

呼叫端只認得領域錯誤，不必知道 `database/sql`。沒有這段，查不到會被當成一般查詢失敗，變成 500。

### 消費者定義介面，一個 fake 對應一個介面

`auth` package 內已有 `accountFinder`（登入用，`FindByEmployeeID`），所以 `/me` 用的介面要取不同名字 `accountByIDFinder`（`FindByID`）。同一個 package 內型別名稱不能重複，fake 也一樣。

`*account.Repository` 同時滿足兩個介面，不需要 `implements`。Spring 的 `@Mock` 在 Go 裡就是手寫 fake。

### 防禦性分支

`GetCurrentAccount` 的三種非 200 結果：

- ctx 沒有 `accountID`（通常是新增 operation 時忘了加進 `Authenticate` map）→ 401。用 `(0, false)` 的 `ok` 判斷，不拿 0 去查 DB
- `FindByID` 回 `ErrNotFound` → 401
- 其他錯誤 → 寫 log，回 500

### 為什麼查不到回 401 不是 404

`/me` 的 id 來自 Cookie 對應的 session，呼叫者無法指定要查哪個資源，所以沒有「資源不存在」的情境。Cookie 對應的身分已不存在，語意上等同未登入。

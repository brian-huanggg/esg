# Step 2.2：Go 連線與 connection pool

## 目標與結果
後端啟動時連上 MariaDB 並 ping。DB 連不上就印一行 JSON 錯誤 log，以 exit 1 結束。
`make test` 通過，後端覆蓋率 90.0%（門檻 80%）。

## 學到的概念

**driver 與 `database/sql`**：標準庫只定義介面，driver 靠 import 的副作用（`init()`）註冊名字。

```go
import "github.com/go-sql-driver/mysql" // 有用到符號，所以不是 `_` import
db, err := sql.Open("mysql", dsn)       // 只檢查 DSN 格式，不連線
err = db.PingContext(ctx)               // 這行才真的連線
```

**`*sql.DB` 是連線池，不是單一連線**
- `SetMaxOpenConns`：同時最多幾條，必須低於 MariaDB 的 `max_connections`（預設 151）
- `SetMaxIdleConns`：閒置時保留幾條
- `SetConnMaxLifetime`：用滿多久就換新，避免被中間設備默默切斷

**DSN**：用 `mysql.Config.FormatDSN()` 組，密碼有特殊字元也能正確跳脫。
`ParseTime=true` 讓 `DATETIME` 掃成 `time.Time`；`Loc=time.UTC` 對應「唯一的時鐘是 DB 時間（UTC）」。

**設定從環境變數讀**：secret 沒有預設值，缺了就啟動失敗。`.env` 靠 Makefile 的 `set -a && . ../.env` 匯出給 `go run`。

**錯誤是回傳值**：用 `fmt.Errorf("...: %w", err)` 包裝，保留原始錯誤。

## 學習者提出的問題與解答
- Q：測試裡 `loc=UTC` 為什麼找不到？
  A：`FormatDSN` 遇到預設值會省略參數，UTC 正是 driver 的預設。改用 `mysql.ParseDSN` 解析後檢查欄位，比字串比對可靠。
- Q：`curl /api/v1/health` 回 404？
  A：路徑以 `api/openapi.yaml` 為準，是 `/api/health`。

## 踩到的坑
- `run` 在失敗時寫成 `return nil`，結果進程無聲結束，沒有錯誤 log，也不是 exit 1。要回報錯誤就回傳 `err`。
- 測試條件寫反：期待有 error，卻寫 `err != nil` 就 `t.Fatal`。寫完測試要確認「它會在該失敗時失敗」。

## 自我檢查
1. 拿掉 `PingContext` 會怎樣？
   答：啟動成功並印 `listening`，因為 `sql.Open` 不連線。錯誤要等到第一個查詢的請求才出現。
2. `SetMaxOpenConns(500)` 而 `max_connections` 是 151？
   答：MariaDB 不會壞，但第 152 條以後的連線被拒絕（`Too many connections`），那些請求失敗。

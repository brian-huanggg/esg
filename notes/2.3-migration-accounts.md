# Step 2.3：migration，accounts 表

## 目標與結果
`make migrate-up` 建出 `accounts` 表，`make migrate-down` 還原，再 `migrate-up` 可重複套用。
`SHOW CREATE TABLE accounts` 看得到兩個 `UNIQUE KEY` 和兩個 `CHECK`；重複工號、非 6 碼數字工號都被 DB 擋下。
`make test` 通過，後端覆蓋率 90.0%（門檻 80%）。

## 學到的概念

**Migration 是 schema 的版本控制**：一個版本一對檔案，`up` 往前、`down` 還原。
`golang-migrate` 在 DB 裡的 `schema_migrations` 表記錄目前版本。
Spring 對應 Flyway，但 Spring Boot 會在啟動時自動跑；Go 要自己下指令（刻意的明確性）。

```
backend/migrations/000001_create_accounts.up.sql    -- CREATE TABLE accounts (...)
backend/migrations/000001_create_accounts.down.sql  -- DROP TABLE IF EXISTS accounts
```

**雙 ID**：`id BIGINT UNSIGNED AUTO_INCREMENT` 是內部主鍵（JOIN、index 快）；
`uuid UUID`（MariaDB 10.7+ 原生型別）是對外 ID，猜不到下一筆。UUID 由應用程式產生（Step 2.6）。

**約束交給 DB**
```sql
UNIQUE KEY uq_accounts_employee_id (employee_id),
CONSTRAINT ck_accounts_employee_id CHECK (employee_id REGEXP '^[0-9]{6}$')
```
約束命名（`uq_`、`ck_`）讓錯誤訊息和之後的 `DROP` 好辨認。

**時間由 DB 填**：`created_at DATETIME(3) NOT NULL DEFAULT UTC_TIMESTAMP(3)`。

**Makefile**
```makefile
MIGRATE = set -a && . ./.env && set +a && \
	migrate -path backend/migrations \
	-database "mysql://$$DB_USER:$$DB_PASSWORD@tcp(127.0.0.1:3306)/$$DB_NAME"
migrate-down:
	$(MIGRATE) down 1   # 不帶數字會互動式詢問，有多版時會一次退光
```
Make 裡 `$` 要寫成 `$$`，shell 才拿得到變數。

## 踩到的坑
- `migrate-down` 一開始漏了 `1`。`migrate down` 不帶數字會問 `[y/N]`，且是退光所有版本。

## 自我檢查
1. 拿掉 `UNIQUE`，改成 service 先 `SELECT` 再 `INSERT`，兩人同時註冊同工號會怎樣？
   - 初答：DB 會報 conflict。這是錯的，因為 UNIQUE 已經拿掉，DB 不會報錯。
   - 正確：兩邊的 `SELECT` 都看到空的，兩個 `INSERT` 都成功，表裡有兩筆相同工號。
     這種競態叫 check-then-act（TOCTOU）。UNIQUE 讓 DB 在 `INSERT` 當下原子地擋下第二筆。
2. `created_at` 為什麼用 `DEFAULT UTC_TIMESTAMP(3)`，而不是 Go 的 `time.Now()`？
   - 答：多個 pod 的時鐘有偏差，各語言的 `now()` 實作也不同。統一用 DB UTC 時間，才有單一時鐘。

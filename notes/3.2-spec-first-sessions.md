# Step 3.2：規格先行，登入、登出、目前帳號

## 目標與結果
`api/openapi.yaml` 新增 `POST /api/sessions`、`DELETE /api/sessions/current`、`GET /api/accounts/me`、
`cookieAuth` securityScheme、共用的 `Unauthorized` 回應和 `CreateSessionRequest`。
`make gen` 重新產生後，新的 `auth.SessionHandler` 三個方法都回 501 stub。
`make test` 通過，後端覆蓋率 91.3%（門檻 80%），三個 `curl` 都回 `501`。對應 PRD 2.2 登入、錯誤順序表第 1 項（401）。

## 學到的概念

**Session 當資源**：登入不是動詞 `/login`，而是「建立一個 session」。

| 動作 | 端點 | 成功 |
| --- | --- | --- |
| 登入 | `POST /api/sessions` | 201 + `Set-Cookie` |
| 登出 | `DELETE /api/sessions/current` | 204 |
| 我是誰 | `GET /api/accounts/me` | 200 + Account |

**OpenAPI cookie 認證**：`securitySchemes` 宣告 `cookieAuth`（`type: apiKey`、`in: cookie`、`name: session`），需要登入的操作再加 `security`。
這只是宣告，`oapi-codegen` 不會自動驗證。驗證要在 Step 3.4 手寫（Spring 裡是 Spring Security 的 filter chain）。

**`Set-Cookie` 寫進回應標頭規格**：session token 不放 body，body 只回 `Account`。生成的 201 型別會多一個 `Headers` 欄位。

**`components/responses` 重用**：三個端點共用一份 `Unauthorized`，用 `$ref: "#/components/responses/Unauthorized"` 引用。

**登入的 401**：帳號不存在和密碼錯誤回同一個 401，避免攻擊者探測工號有沒有註冊。

**內嵌欄位名就是型別名**：
```go
type server struct {
	*account.Handler
	*auth.Handler // two fields named "Handler": compile error
}
```
所以 auth 的型別取名 `SessionHandler`。這是型別宣告錯誤，編譯階段就失敗，不會到 runtime。

## 問題與解答
- **`make gen` 出現 `map key "schema" not found`**：`$ref` 路徑寫成 `#/components/schema/Error`，少了 `s`。路徑要和 `components.schemas` 完全一致。
- **body 的 `requestId` 是空字串**：stub 沒填。`X-Request-Id` 標頭有值，3.4 實作時用 `middleware.RequestIDFrom(ctx)` 填。

## 自我檢查
1. 規格宣告 `GET /api/accounts/me` 要 `cookieAuth`，沒帶 cookie 為什麼回 501 而不是 401？
   答：`security` 只是宣告，驗證還沒寫，請求直接進到 stub handler。
2. `server` 同時內嵌 `*account.Handler` 和 `*auth.Handler` 會怎樣？
   答：兩個內嵌欄位都叫 `Handler`，編譯失敗，不會進到 runtime。

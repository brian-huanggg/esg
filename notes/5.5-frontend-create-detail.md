## 學到的概念

### `useNavigate`：程式內換頁

類似 Spring 的 `redirect:/...`。成功建立後換頁：

```tsx
const navigate = useNavigate()
void navigate(`/proposals/${data.id}`)
```

### `useParams`：讀路徑變數

類似 Spring 的 `@PathVariable`。路由寫 `:id`，元件裡讀出來：

```tsx
const { id } = useParams<{ id: string }>()
```

### openapi-fetch 的 `data` / `error` 互斥

2xx 時有 `data`，其他狀態有 `error`，型別來自 `schema.d.ts`。
詳情頁額外用 `response.status === 404` 區分「找不到」和其他錯誤。

### 404 的語意

後端對「不存在」和「不是你的」都回 404（專案不變量：沒有權限一律回 404）。
前端一律顯示 Not found，不洩漏提案是否存在。

### 導向用 body 的 `id`，不解析 `Location`

`Location` 是 API 路徑 `/api/proposals/{id}`，前端路由是 `/proposals/{id}`，
少了 `/api`。要用就得自己拆字串再重組，很脆弱。body 的 `id` 有型別，直接用。

### CSRF

建立頁沒有寫任何 CSRF 程式碼，`api/client.ts` 的 middleware 會對非安全方法
自動帶 `X-CSRF-Token`（跟 Step 4 一樣）。

## 自我檢查

1. 建立成功後為什麼用 `data.id` 導向，而不是解析 `Location`？
   答：`Location` 是 API 路徑，不是前端路由，要拆字串重組；body 的 `id` 有型別、可直接用。
2. 開別人提案的 `/proposals/<id>` 會看到什麼？
   答：Not found。後端對不存在和不是你的都回 404，頁面把 404 對應到 notFound 狀態。

# 5.3 提案 Repository：Create、依擁有者取得、1062

## 目標與結果

建立 `backend/internal/proposal/repository.go`：

- `Create`：寫入提案，回填 `ID`、`UUID`、`Version`、`CreatedAt`、`UpdatedAt`
- `FindByUUID(ctx, leaderID, uuid)`：只有擁有者查得到
- 同一位 Leader 標題重複（不分大小寫）時回 `ErrDuplicateTitle`

整合測試 6 個全部通過，驗收條件「別人的提案拿到 not found」成立。`make test` 的後端覆蓋率是 90.0%。

## 學到的概念

### 1. 授權條件寫進 SQL

```go
`SELECT ... FROM proposals WHERE uuid = ? AND leader_account_id = ?`
```

「不存在」和「不是你的」都是 0 列，都會變成 `sql.ErrNoRows`，再轉成 `ErrNotFound`。
這就是不變量「沒有權限一律 404」在資料層的寫法。
`leaderID` 放在函式簽名裡，呼叫的人不可能忘記傳擁有者。

Spring 類比：像 Spring Data 的 `findByUuidAndLeaderId(...)`。差別是 Go 的 SQL 要自己寫，`Scan` 也要自己寫。

### 2. `LastInsertId()` 取得 AUTO_INCREMENT

```go
res, err := r.db.ExecContext(ctx, `INSERT ...`, ...)
p.ID, err = res.LastInsertId()
```

JPA 的 `save()` 會自動回填 `@Id`，Go 要自己從 `sql.Result` 拿。
`version`、`created_at` 和 `updated_at` 來自欄位 DEFAULT（資料庫時鐘），所以要再 SELECT 一次把它們讀回來。

### 3. 1062 要比對 key 名稱

```go
if errors.As(err, &me) && me.Number == 1062 &&
    strings.Contains(me.Message, "uq_proposals_leader_title") {
    return ErrDuplicateTitle
}
```

`proposals` 表有兩個 UNIQUE key（`uuid` 和 `(leader, title)`），違規時錯誤碼都是 1062。
只看 1062 的話，UUID 撞號會被誤報成「標題重複」。

### 4. 測試資料：`seedAccount`

FK 要求 leader 必須存在，所以測試直接用 SQL 插一筆 account，不 import `account` 套件，避免套件之間互相依賴。
`"SOLAR ROOF"` 和 `"Solar roof"` 會撞號，因為 collation `utf8mb4_uca1400_ai_ci` 不分大小寫。

## 自我檢查

1. **把授權改成 `WHERE uuid = ?`，再用 Go 的 `if` 檢查擁有者，差在哪？**
   答：對外行為一樣，但別人的資料已經被讀進記憶體。其他查詢也很容易忘了寫那個 `if`。寫在 SQL 裡比較安全。
2. **刪掉 key 名稱比對，只看 1062，會怎樣？**
   答：UUID 撞號會被誤報成 `ErrDuplicateTitle`。擋住重複的是資料庫約束，Go 只負責翻譯錯誤，所以重複標題仍然會被擋。

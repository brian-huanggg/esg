# 3.1 migration：`sessions` 表

## 目標與結果

建立 `sessions` 表。`token_hash` 有 UNIQUE，`account_id` 有外鍵指向 `accounts`。
`make migrate-up` 和 `make migrate-down`（只回退一步）都能執行。

檔案：

- `backend/migrations/000002_create_sessions.up.sql`
- `backend/migrations/000002_create_sessions.down.sql`

## 學到的概念

### Session 與 JWT 的取捨

| | Session（server-side） | JWT（stateless） |
|---|---|---|
| 狀態存哪 | 資料庫 | token 本身 |
| 登出 | 刪一列，立刻失效 | 要等過期，或另做黑名單 |
| 閒置逾時 | 更新 `last_seen_at` | 要每次換發新 token |

PRD 要求閒置 30 分鐘逾時、登出立刻失效，所以選 Session。代價是每個請求都要查一次資料庫。
Spring 對應：Spring Session JDBC。

### 為什麼只存雜湊

cookie 放 32 bytes 的隨機 token，資料庫只存 `SHA-256(token)`。資料庫外洩時，攻擊者拿到的是雜湊，
雜湊是單向的，還原不出能放進 cookie 的值。

- 密碼用 bcrypt：密碼由人設定，熵低，需要刻意變慢。
- token 用 SHA-256：token 有 256 bits 隨機熵，無法窮舉，不需要變慢。

### 用資料庫時間判斷逾時

`created_at`、`last_seen_at` 都用 `DEFAULT UTC_TIMESTAMP(3)`。應用程式不呼叫 `time.Now()`，
多個 pod 時鐘不一致也不影響結果。兩種逾時各用一個欄位：

- 絕對逾時（8 小時）：`expires_at`，建立時算好，之後不變。它沒有 default，由 3.3 的 INSERT 用資料庫時間算。
- 閒置逾時（30 分鐘）：`last_seen_at`，每次請求更新，查詢時比較。

### 最小例子

```sql
CREATE TABLE sessions (
  id           BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  token_hash   BINARY(32)      NOT NULL,
  account_id   BIGINT UNSIGNED NOT NULL,
  created_at   DATETIME(3)     NOT NULL DEFAULT UTC_TIMESTAMP(3),
  last_seen_at DATETIME(3)     NOT NULL DEFAULT UTC_TIMESTAMP(3),
  expires_at   DATETIME(3)     NOT NULL,
  PRIMARY KEY (id),
  UNIQUE KEY uq_sessions_token_hash (token_hash),
  CONSTRAINT fk_sessions_account FOREIGN KEY (account_id)
    REFERENCES accounts (id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

- `BINARY(32)`：SHA-256 輸出 32 bytes，存原始 bytes 比 64 字元 hex 省一半空間。
- `UNIQUE`：資料庫拒絕重複雜湊，同時是用 hash 查詢時的索引。
- `ON DELETE CASCADE`：帳號刪除時 session 一起刪，避免孤兒資料。
- Session 不對外暴露，所以沒有 `uuid` 欄位。

### migration 檔名

`golang-migrate` 用數字前綴（`000002`）把 `up` 和 `down` 配成一對，名稱不同不會報錯。
這一步 up 檔曾誤寫成單數 `create_session`，後來改成跟 down 檔一致的 `create_sessions`。
版本號沒變，所以不影響已套用的 migration。

## 學習者的問題與解答

**Q：如何讓 `make db-exec` 不需要輸入密碼？**
`-p` 不帶值會互動詢問。改成在容器內設定 `MYSQL_PWD` 環境變數，再拿掉 `-p`：

```makefile
db-exec:
	$(COMPOSE) exec db sh -c 'MYSQL_PWD="$$MARIADB_PASSWORD" mariadb -u esg $$MARIADB_DATABASE'
```

`$$` 讓 Make 傳出單一 `$`，變數才會在容器內展開，密碼不會出現在本機的指令列。
變數名稱需對照 `deploy/compose.yaml`。這個修改尚未套用。

## 自我檢查

1. 判斷「閒置超過 30 分鐘」，哪種做法符合「唯一的時鐘是資料庫時間」？
   答：用 SQL 比較 `last_seen_at` 與 `UTC_TIMESTAMP(3)` 減 30 分鐘。
   在 Go 用 `time.Now()` 算門檻會違反不變量；背景掃描和 cookie `Max-Age` 都無法精確表達閒置逾時。
2. 資料庫外洩時，為什麼只存 `token_hash` 能降低風險？
   答：cookie 要送出的是原始 token，雜湊無法反推出它。
   SHA-256 其實很快，之所以安全是因為 token 有 256 bits 隨機熵，無法窮舉，而不是因為雜湊慢。

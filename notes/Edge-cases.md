# Edge cases

1. 「稽核失敗則整筆失敗」vs「被拒絕的嘗試也要記錄」
2. 「下載」要記稽核 vs 「MinIO 故障時下載回 503」
3. 「DB 時間是唯一時鐘」vs Galera 多節點
4. 「提案一定附有簡報」vs 上傳失敗 / MinIO 故障
5. 截止瞬間：請求在 OPEN 時進來，處理中途跨過截止。判斷必須在寫入的同一個 transaction 內用 DB 時間，不能「先查狀態、再寫入」(TOCTOU)。
6. 重複送出：multipart 建立沒有 idempotency key，雙擊或網路逾時重試會產生重複請求。你現在靠 UNIQUE(leader, name) 擋住，但使用者會看到 409，要想好文案與行為。
7. 鎖定機制本身是攻擊面：6 碼工號可被枚舉，攻擊者故意輸錯 5 次就能鎖死任何同事（DoS）。要決定：不存在的帳號也要計數嗎（否則可從鎖定行為推測帳號存在）？鎖定期間輸入正確密碼回什麼？
8. 鎖定的「IP」是哪一層
9. Admin 與一般帳號衝突：Vault 同步來的 Admin 工號若已被人註冊怎麼辦？Admin 從 Vault 移除後，既有 session 要即時失效嗎？Vault 不可用時，同步不能把 Admin 清空（fail-safe）。
10. 攻擊流量放大：登入失敗要記稽核，暴力攻擊會讓稽核表暴增。要考慮取樣、彙總或獨立限速。
11. Hash chain 的序列化瓶頸：每筆要引用上一筆的 hash，並發寫入必須串行，在 Galera 多主下很痛。要評估吞吐量，或改成每個分區各自一條鏈。
12. Readiness probe 不應依賴 MinIO：否則 MinIO 一掛，pod 全部下線，連 PRD 要求「仍可成功的刪除」也做不了。
13. 優雅關閉：K8s 滾動更新時，進行中的上傳、下載和背景 worker 要在 SIGTERM 後有收尾時間。
14. 計數器必須在 DB：鎖定與限速不能放記憶體（多 pod），PRD 已放 MariaDB，方向正確。

# 4.8 platform-gitops：esg-backend chart

## 目標與結果

在 platform-gitops 新增 `apps/esg/backend/` chart，包含 Deployment、Service 和 PreSync migrate Job。
完成後：

- `helm template esg-backend apps/esg/backend --set image.tag=abc1234 --set migrate.image.tag=abc1234` render 成功
- 沒帶 tag 時 render 失敗，不會默默拉到 `latest`

這一步只改 platform-gitops（`~/Workspace/tools/gcp-vm-playground/gitops`），ESG repo 沒有程式碼變更。
chart 不會被部署，要到 4.10 加上 `registry/esg-backend.yaml` 才由 ArgoCD 接手。

## 概念

### Chart 的結構

Spring 類比：`values.yaml` 像 `application.yaml`，`values-dev.yaml` 像 `application-dev.yaml`。

- `Chart.yaml`：名稱和版本
- `values.yaml`：預設值。`values-dev.yaml`：環境覆寫，tag 由 4.11 填入
- `templates/`：帶參數的 YAML

### `required`：tag 空著就失敗

```yaml
image: "{{ .Values.image.repository }}:{{ required "image.tag is required (git SHA)" .Values.image.tag }}"
```

沒帶 tag 時，Helm 先踩到哪個 `required` 就報哪個，所以可能看到的是 `migrate.image.tag is required`。結果相同：render 失敗。

### PreSync hook

```yaml
annotations:
  argocd.argoproj.io/hook: PreSync
  argocd.argoproj.io/hook-delete-policy: BeforeHookCreation,HookSucceeded
```

- Job 是一般 template，hook annotation 才讓它變成「sync 前先跑」。Spring 類比：啟動時先跑 Flyway
- 沒有這個 annotation，Job 和 Deployment 一起套用，新 Pod 可能比 schema 升級更早啟動
- `BeforeHookCreation`：下一次 sync 先刪掉舊 Job 再建新的。`HookSucceeded`：成功後清掉

### wait-for-db initContainer

kube-router 要等 NetworkPolicy 把 Pod IP 加進允許清單，太早連 MariaDB 會被拒絕。
initContainer 每 2 秒 `mariadb-admin ping`，最多 30 次，通了才讓 migrate 容器啟動。
image 沿用 MariaDB 自己的 `lab/mariadb-base`，Harbor 裡已經有。

### ENTRYPOINT 與 args

`Dockerfile.migrate` 的 `ENTRYPOINT ["migrate", "-path", "/migrations"]`。
Kubernetes 的 `args` 對應 Docker 的 `CMD`，會接在 `ENTRYPOINT` 後面；`command` 才會取代 `ENTRYPOINT`。

```yaml
args: ["-database=$(DATABASE_URL)", "up"]
# 實際執行：migrate -path /migrations -database=<url> up
```

`$(DATABASE_URL)` 是 Kubernetes 的環境變數展開，不是 Helm 語法。

### Go 要手動接線的地方

`envFrom.secretRef: esg-db` 把 Secret 的每個 key 變成環境變數。
Spring 會自動把環境變數綁進設定，Go 沒有，所以 `backend/internal/shared/db.go` 用 `os.Getenv` 手動讀。

### 安全設定

`runAsNonRoot`、UID 65532（distroless nonroot）、`readOnlyRootFilesystem`、`capabilities.drop: [ALL]`、
`seccompProfile: RuntimeDefault`、`automountServiceAccountToken: false`。
distroless 沒有 shell，所以 backend 的 probe 只能用 `httpGet`（`/api/health`）。

## 問題與解答

- 沒帶 tag 的錯誤訊息為什麼是 `migrate.image.tag`？Helm 先執行到哪個 `required` 就報哪個。
- 輸出裡的 `&amp;&amp;`？是顯示問題，檔案裡是 `&&`，Helm 的 `|` 區塊不會 escape。

## 自我檢查

1. 拿掉 PreSync annotation 會怎樣？答：Job 變成普通資源，和 Deployment 一起套用，新 backend 可能比 schema 升級更早啟動。
2. Job 只寫 `args: [-database=..., up]`，為什麼不用 `-path /migrations`？答：`args` 接在 image 的 `ENTRYPOINT` 後面，實際執行 `migrate -path /migrations -database=... up`。

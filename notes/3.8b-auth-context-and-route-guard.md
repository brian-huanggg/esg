# 3.8b Auth context、受保護路由、登出

## 目標與結果

未登入打開 `/` 會被導到 `/login`。登入後看得到首頁和 Logout 按鈕，重新整理仍維持登入。按 Logout 後 `DELETE /api/sessions/current` 回 204，兩個 cookie 被清掉，頁面回到 `/login`。

瀏覽器驗證通過。`make test`、`make lint-frontend`、`make format-frontend` 通過，後端覆蓋率 90.7%。

檔案：

- `frontend/src/auth/context.ts`：`AuthState`、`AuthContext`、`useAuth`
- `frontend/src/auth/AuthProvider.tsx`：掛載時 `GET /api/accounts/me`，提供 `login` / `logout`
- `frontend/src/auth/RequireAuth.tsx`：路由守衛
- `frontend/src/main.tsx`：用 `AuthProvider` 包住 `App`
- `frontend/src/pages/Login.tsx`：成功時 `login(data)` 再 `navigate('/')`
- `frontend/src/App.tsx`：受保護路由、Logout 按鈕
- `frontend/src/App.test.tsx`：包 `AuthProvider`，mock 依網址分流

## 學到的概念

### 前端怎麼知道有沒有登入
`session` 是 HttpOnly，JS 讀不到，所以只能問後端 `GET /api/accounts/me`：200 是登入，401 是未登入。`openapi-fetch` 的 401 不丟例外，而是回 `data: undefined`；只有網路層錯誤才會進 `catch`。

### React Context
讓整棵元件樹共用資料，不用一層層傳 props。類比 Spring 的 `SecurityContextHolder`，但 React Context 綁在元件樹上，只有 Provider 包住的子孫讀得到。

```tsx
const Ctx = createContext('guest')

<Ctx.Provider value="rong">
  <Child />   {/* useContext(Ctx) === 'rong' inside Child */}
</Ctx.Provider>
```

### 三種狀態，不是兩種
`loading` / `anonymous` / `authenticated`。沒有 `loading` 的話，重新整理時 `/me` 還沒回來就會被當成未登入而導到 `/login`。

### 路由守衛
`RequireAuth` 讀狀態後決定顯示 `Loading...`、`<Navigate to="/login" replace />` 或 `<Outlet />`。沒有 `path` 的 `<Route element={<RequireAuth />}>` 只負責包住底下的路由。這只是 UX，真正的權限在後端。

### 手動接線
Spring Security 靠 filter chain 自動攔截。這裡 Provider 要在 `main.tsx` 手動掛、守衛要在 `App.tsx` 手動包。

### 檔案拆分
`react-refresh` 規則要求元件檔只 export 元件，所以 `createContext` 和 `useAuth` 放在 `context.ts`，`AuthProvider` 另一個檔案。

### 先更新狀態再導頁
`Login` 成功時要 `login(data)` 再 `navigate('/')`。React 通常會把同一個事件處理函式裡的更新批次處理，順序倒過來多半也能跑，但不該依賴這個細節。

## 測試

`App` 現在一定要在 `AuthProvider` 裡，所以 `App.test.tsx` 的 `renderApp` 要包 `AuthProvider`。`App` 會發兩種請求（`/api/accounts/me`、`/api/health`），mock 要依網址分流。

```tsx
const fetchMock = vi.fn((input: RequestInfo | URL) => {
  const url = input instanceof Request ? input.url : String(input)
  if (url.endsWith('/api/accounts/me')) {
    return Promise.resolve(new Response(ACCOUNT, { status: 200 }))
  }
  return Promise.resolve(new Response(body, { status }))
})
```

- `openapi-fetch` 傳 `Request` 物件，`getHealth` 傳字串，兩種都要處理。
- 每次呼叫 new 一個 `Response`，因為 body 只能讀一次。
- 這是手寫 fake，不是 Mockito 的 `when().thenReturn()`。

## 學習者的問題

問：完整的 `Login.tsx` 和 `App.tsx` 長怎樣？
答：`Login.tsx` 比 3.8a 多了 `useAuth` 的 import 和 `login`，成功判斷從 `if (!apiError)` 改成 `if (data)`。`App.tsx` 多了 `Login`、`RequireAuth`、`useAuth` 的 import，`/` 路由包進 `<Route element={<RequireAuth />}>`，畫面多一個 Logout 按鈕。

## 自我檢查

1. `Login` 成功時若先 `navigate('/')` 再 `login(data)` 會怎樣？
   答：`RequireAuth` 讀到的狀態可能還是 `anonymous`，會被導回 `/login`。
2. 為什麼要 `loading` 狀態？
   答：避免重新整理時 `/me` 還沒回來就被導到 `/login`。

# 4.7 platform-gitops：esg-db ExternalSecret 與 MariaDB 放行

## 目標與結果

在 platform-gitops 讓 `esg` namespace 產生 Secret `esg-db`，並讓 `esg` 的 Pod 能連上共用的 MariaDB。
完成後：

- `kubectl -n esg get externalsecret esg-db` 顯示 `SecretSynced`
- `esg-db` 有 6 個 key：`DB_HOST`、`DB_PORT`、`DB_NAME`、`DB_USER`、`DB_PASSWORD`、`DATABASE_URL`
- `harbor-pull` 仍然正常

這一步只改 platform-gitops（`~/Workspace/tools/gcp-vm-playground/gitops`），ESG repo 沒有程式碼變更。

## 概念

### ExternalSecret 與 template

ESO（External Secrets Operator）在叢集裡把 Vault 的值同步成原生 K8s Secret。
Spring 類比：Spring Cloud Vault，但 ESO 在叢集端完成，app 不知道 Vault 存在。

Vault 只存 `username`、`password`，app 需要 `DB_*`，migrate 需要 `DATABASE_URL`，
所以用 `target.template.data` 組出來：

```yaml
template:
  data:
    DB_USER: "{{ .username }}"
    DATABASE_URL: "mysql://{{ .username }}:{{ .password }}@tcp(mariadb.databases.svc.cluster.local:3306)/esg"
data:
  - {secretKey: username, remoteRef: {key: k3s/esg/db, property: username}}
```

- `remoteRef.key` 不含 `secret/`，因為 SecretStore 已設 `path: secret`
- host、port、database 不是機密，直接寫在 template
- 密碼只有英數字，放進 URL 不用 escape

### NetworkPolicy 的 `from` 清單

同一個 `from:` 清單裡的多個項目是 **OR**：

```yaml
- from:
    - namespaceSelector: {matchLabels: {kubernetes.io/metadata.name: mall}}
    - namespaceSelector: {matchLabels: {kubernetes.io/metadata.name: esg}}
```

mall 或 esg 的 Pod 都能連 3306。NetworkPolicy 選到 Pod 後預設拒絕，沒列出的來源都進不來。
只有 `namespaceSelector` 和 `podSelector` 寫在**同一個項目**裡才是 AND。

### ESO 是非同步的

Pod 比 Secret 早起時，Pod 物件會被 API server 接受，但 kubelet 找不到 Secret，
卡在 `CreateContainerConfigError` 並持續重試，Secret 出現後自動啟動。
Argo CD 的 sync-wave 只管 Application 之間的順序，跨 Application 只保證最終一致。

## 問題與解答

**為什麼新增的 `externalsecret-db.yaml` 在 `git status` 看不到？**
platform-gitops 的 `.gitignore` 有一條 `secrets/`，會擋住任何路徑下的 `secrets/` 資料夾，
所以 `apps/esg/secrets/` 底下的**新檔案**都被忽略。已追蹤的舊檔不受影響，所以舊檔看起來正常、新檔消失。
診斷指令：`git check-ignore -v <path>`。

修法：把規則綁在根目錄，並放行公開金鑰：

```gitignore
/secrets/*
!/secrets/jwks.json
!/secrets/pubkeys.pem
```

- 用 `/secrets/*` 而不是 `/secrets/`：git 無法從已被忽略的資料夾裡撈回檔案
- `!` 規則要放在 `*.pem` 之後，才能蓋過它

**為什麼 4.7 不處理密碼輪替？**
`refreshInterval: 1h` 只更新 Secret，已啟動的 Pod 不會重讀 `envFrom`，要重啟 Pod 才生效。

## 自我檢查

1. `from:` 清單裡有 mall 和 esg 兩個 `namespaceSelector`，允許哪些來源？
   答：mall **或** esg 的 Pod。清單的每一項各自判斷。
   常見誤解：以為是 AND（沒有 namespace 能同時叫兩個名字）、以為後面的項目被忽略、以為會放行全部。
2. Pod 比 ESO 建立 Secret 早啟動會怎樣？
   答：Pod 卡在 `CreateContainerConfigError`，kubelet 重試，Secret 出現後自動啟動。
   常見誤解：以為 API server 會拒絕 Pod、以為變數會是空值、以為 Argo CD 會等 ExternalSecret Ready。

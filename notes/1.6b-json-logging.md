# 1.6B JSON log 與 access log middleware

> tag：`step-01-06`（1.6A + 1.6B 合起來）
> 檔案：`backend/internal/shared/middleware/logging.go`、`logging_test.go`、`backend/cmd/api/main.go`、`main_test.go`
> 對應：PRD 3.3「每一行 log 都是 JSON，都帶 request-id」：這一步全部完成

## 目標與結果

每個請求在伺服器終端機印出一行 JSON，裡面有 method、path、status、duration_ms、request_id。

- `make test` 全部通過（新增 `TestLogging`）
- 4 個 curl 對應 4 行 log，每行的 `request_id` 都等於 curl 看到的 `X-Request-Id`
- POST 記到 `"status":405`：mux 自己回的錯誤也有記錄
- `-H 'X-Request-Id: my-trace-1'` → log 裡是 `"request_id":"my-trace-1"`

## Pseudocode：整體在做什麼

```
RequestID   決定 id，放進 header 和 context（1.6A）
  Logging   按碼表 → 換上會記 status 的 writer → 往裡走 → 回來印一行
    mux → StrictHandler → HealthHandler
```

三個零件各回答一個問題：

| 問題 | 零件 |
|---|---|
| 印成什麼格式、印到哪？ | `slog.NewJSONHandler(os.Stdout, nil)` |
| 怎麼自動帶 request_id？ | `ContextHandler`（蓋章的人） |
| status 是多少？ | `statusRecorder`（會記筆記的傳話筒） |

## 學到的概念

### 0. 三種 Handler 不要搞混

| 名字 | 負責 |
|---|---|
| `http.Handler` | 處理 HTTP 請求（`ServeHTTP(w, r)`） |
| `slog.Handler` | 處理一筆 log：決定格式、加欄位、印出去 |
| `StrictHandler` | Step 1.5 的轉接頭：把有型別的 `HealthHandler` 接到 `http.Handler` |

### 1. slog：Logger 是櫃台，Handler 是後台

```go
type Handler interface {
	Enabled(ctx, level) bool
	Handle(ctx, record) error
	WithAttrs(attrs []Attr) Handler
	WithGroup(name string) Handler
}
```

- `Attr` ＝ log 裡的一個欄位（key + value），例如 `slog.String("request_id", id)`
- `logger.With("user", "bob")` 在背後呼叫 `WithAttrs`：之後每一行都帶 `user`
- `logger.WithGroup("http")` 讓欄位巢狀：`{"http":{"status":200}}`
- `slog.SetDefault(logger)`：套件層級的 `slog.Info` 和舊的 `log` 套件都改走同一個 JSON handler
- `log.Fatal` 印純文字，所以改成 `logger.Error(...)` + `os.Exit(1)`

### 2. 嵌入（embedding）＋只覆寫需要的方法

```go
type ContextHandler struct{ slog.Handler } // field name is the type name: h.Handler

func (h ContextHandler) Handle(ctx context.Context, r slog.Record) error {
	if id := RequestIDFrom(ctx); id != "" { // if-init: id lives only inside the if
		r.AddAttrs(slog.String("request_id", id))
	}
	return h.Handler.Handle(ctx, r)
}

func (h ContextHandler) WithAttrs(attrs []slog.Attr) slog.Handler {
	return ContextHandler{h.Handler.WithAttrs(attrs)} // re-wrap, or the stamp disappears
}
```

- 嵌入讓外層自動擁有內層的方法，所以 `ContextHandler` 已經符合 `slog.Handler`
- **陷阱**：`WithAttrs` / `WithGroup` 不覆寫的話，會回傳裸的 JSON handler，request_id 就不見了

### 3. `InfoContext` 才會把 ctx 交出去

```go
logger.Info("request", ...)                     // handler gets an empty ctx → no request_id
logger.InfoContext(r.Context(), "request", ...) // handler can read the id
```

1.6A 把 id 放進 context，`InfoContext` 把那個 context 交給 log，這條路才算接通。

### 4. statusRecorder：指標 receiver、預設 200

```go
type statusRecorder struct {
	http.ResponseWriter
	status int
}
func (s *statusRecorder) WriteHeader(code int) { s.status = code; s.ResponseWriter.WriteHeader(code) }

rec := &statusRecorder{ResponseWriter: w, status: http.StatusOK}
```

- `http.ResponseWriter` 只能寫、不能讀，所以要自己記
- 要修改 `s.status`，所以用 `*` 指標 receiver；值 receiver 只會改到複本
- 預設 200：只呼叫 `Write` 的 handler 不會經過我們的 `WriteHeader`
- `duration_ms` 是 access log 的標準欄位，用來找出慢的請求。這裡的 `time.Now()` 只用來量時間，不是業務邏輯，沒有違反「唯一時鐘是資料庫」

### 5. 依賴注入（dependency injection）

logger 在 `main` 建立一次，傳給 `run` → `newHandler` → `Logging`，不用全域變數。
好處：測試可以傳別的 logger。

```go
slog.NewJSONHandler(os.Stdout, nil) // production: terminal
slog.NewJSONHandler(&buf, nil)      // test: memory buffer
slog.New(slog.DiscardHandler)       // main_test: drop everything
```

### 6. bytes.Buffer、json.Unmarshal、JSON 數字是 float64

- `bytes.Buffer`：記憶體裡的桶子，符合 `io.Writer`，寫進去之後可以讀回來
- `json.Unmarshal(b, &v)` ＝ TS 的 `JSON.parse`；`json.Marshal` ＝ `JSON.stringify`
- 傳 `&entry` 是因為 Unmarshal 要**填進** entry（跟指標 receiver 同一個道理）
- `map[string]any` ≈ TS 的 `Record<string, unknown>`
- 解析到 `any` 的 JSON 數字一律是 `float64`，所以 `wantStatus` 宣告成 `float64`

## 測試在驗證什麼

| 要確認的事 | 檢查 |
|---|---|
| log 是 JSON | `json.Unmarshal` 失敗就 `Fatalf` |
| request_id 從 header 一路傳到 log | `entry["request_id"] != "trace-1"`（`logging_test.go:40`） |
| status 記對了 | 418 案例：明確寫入；只呼叫 Write 的案例：驗證預設 200 |

- `main_test.go` **不會**失敗：header 是 RequestID 設定的，跟 Logging 無關
  （一開始答成 main_test 會失敗，經提示後更正）

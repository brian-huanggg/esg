# 3.9a 全域 401 處理

## 目標與結果

已登入時 session 過期，任何受保護 API 回 401，畫面自動跳回 `/login`。登入密碼錯（`POST /api/sessions`）和載入時問登入狀態（`GET /api/accounts/me`）的 401 是預期答案，不觸發全域處理。

`npm run build`、`make test`、`make lint-frontend`、`make format-frontend` 通過，後端覆蓋率 90.7%。行為本身（401 → 跳回登入頁）等 3.9b 用測試驗證。

檔案：

- `frontend/src/api/client.ts`：`EXPECTED_401_PATHS`、`setUnauthorizedHandler`、`onResponse` middleware
- `frontend/src/auth/AuthProvider.tsx`：掛載時註冊 handler，卸載時取消

## 學到的概念

### 全域攔截 401
Spring 裡是 `AuthenticationEntryPoint`。這裡的 `api` client 已有 `onRequest`（3.7b 加 CSRF header），再加 `onResponse` 就是對稱的另一半。每個回應都會經過它。

### React 外的程式碼怎麼通知 React
`client.ts` 不是元件，不能呼叫 `setState`。做法是模組層級變數加 setter，由 `AuthProvider` 掛載時把「設為 anonymous」註冊進去，卸載時傳 `null` 取消。Go 裡手動接線的對應是 `main.go` 的 constructor 注入，這裡沒有 DI 容器，所以用 setter。

```ts
let onUnauthorized: (() => void) | null = null
export function setUnauthorizedHandler(h: (() => void) | null) {
  onUnauthorized = h
}
// in middleware
onUnauthorized?.()
```

### 不在 middleware 裡導向
handler 只改 state。state 變 `anonymous` 後，`RequireAuth` 本來就會渲染 `<Navigate to="/login" replace />`。導向的責任只放在一處。

### 例外清單
`/api/sessions` 的 401 是「密碼錯」，`/api/accounts/me` 的 401 是「沒登入」。兩者都不是「session 過期」，所以放行。刪掉例外清單後，這兩個路徑的 401 也會呼叫 handler，條件變多，而不是變少。現在剛好無害，但 handler 以後若加副作用（清快取、跳提示），誤觸發就會變成 bug。

## 自我檢查

**Q1：刪掉 `onResponse` 裡放行 `/api/sessions` 和 `/api/accounts/me` 的判斷，會怎樣？**
答案：登入密碼錯時，`POST /api/sessions` 的 401 也會觸發全域 handler。handler 被呼叫的條件變多。真正 session 過期的 401 本來就不在例外裡，不受影響。

**Q2：handler 把 state 設成 `anonymous` 後，使用者怎麼被導回 `/login`？**
答案：`RequireAuth` 讀到 `anonymous`，渲染 `<Navigate to="/login" replace />`。middleware 不碰路由。

`/api/health` 改由 `shared.HealthHandler` 實作 oapi-codegen 產生的 `StrictServerInterface`，

## 學到的概念

### 1. Handler（處理器）

拿到 request、負責寫出 response 的那段程式。比喻：餐廳櫃台人員；路由器（mux）是帶位員。
標準庫的正式定義本身就是一個 interface：

```go
type Handler interface {
    ServeHTTP(w http.ResponseWriter, r *http.Request)
}
```

### 2. Interface（介面）＝插座的形狀

定義一組方法的名稱、參數、回傳值。Go 是**隱式實作**：方法對得上就自動符合，不用寫 `implements`。

```go
type Speaker interface{ Speak() string }
type Dog struct{}
func (Dog) Speak() string { return "woof" }
var s Speaker = Dog{} // OK, no "implements" needed
```

| | Go | TypeScript | Java |
|---|---|---|---|
| 宣告實作 | 不用寫 | 不用寫（結構型別） | 一定要寫 `implements` |
| 執行時還在嗎 | 在（可以做型別斷言） | 不在 | 在 |

### 3. 兩節轉接頭：你只寫一層

```
你的 GetHealth ──[api.NewStrictHandler]──> ServerInterface ──[api.HandlerFromMux]──> http.ServeMux
 (ctx, req) → (resp, error)                  (w, r)                                     註冊 GET /api/health
```

- 你只交出「答案」（回傳值），header、狀態碼、JSON 編碼都由產生的程式碼處理
- 路由也從規格產生，不用再自己寫 `mux.HandleFunc`

```go
func (h *HealthHandler) GetHealth(_ context.Context, _ api.GetHealthRequestObject) (api.GetHealthResponseObject, error) {
	return api.GetHealth200JSONResponse{Status: api.Ok}, nil
}
```

### 4. 編譯器怎麼檢查規格和實作一致

- 檢查發生在**使用**的地方：`api.NewStrictHandler(&shared.HealthHandler{}, nil)` 的參數型別是
  `StrictServerInterface`，形狀不對這行就編譯不過（Java 會報在 class 宣告，Go 報在使用處）
- 狀態碼由**回傳哪個型別**決定（`GetHealth200JSONResponse` 一定寫 200），body 由欄位內容決定
- 編譯器**只讀 `.go` 檔**：改了 `openapi.yaml` 沒跑 `make gen`，`go build` 什麼都不會發現

### 5. 其他新語法

- **方法與 receiver**：`func (h *HealthHandler) GetHealth(...)`，方法寫在 struct 外面，用 receiver 掛上去
- **`&` 與指標**：`&HealthHandler{}` 取地址。方法掛在 `*HealthHandler` 上，所以只有指標符合介面。
  Go 的 struct 預設傳值（複製），TS 的物件本來就是傳參考
- **`_` 參數**：只拿掉名字，位置和型別還在，因為參數列是形狀的一部分。TS 可以省略尾端參數，Go 不行
- **多回傳值與 `error`**：Go 沒有例外，錯誤是最後一個回傳值，成功回 `nil`
- **型別斷言**：`got, ok := resp.(api.GetHealth200JSONResponse)`，執行時真的檢查；
  不接 `ok` 時型別不對會 panic。TS 的 `as` 只騙編譯器、執行時不檢查
- **`t.Fatalf` vs `t.Errorf`**：Fatalf 立刻停止這個測試，後面的檢查沒意義時用
- **未使用的 import 是編譯錯誤**：刪掉 `handleHealth` 後要一起刪 `encoding/json`

### 6. `context.Context`

請求的「外送單附註」：取消、期限、跟這個請求有關的值（1.6 的 request-id）。
慣例是會做 I/O 的函式第一個參數就放 `ctx`。health 不查資料庫，所以用 `_`。

## 學習者的問題

**Q：三層介面看不懂。**
A：換成轉接頭比喻：路由器（牆上插座）只收 `func(w, r)`；你寫的是 strict 形狀
`(ctx, req) → (resp, error)`；中間兩節轉接頭是 oapi-codegen 產生的，不用理解內部。

**Q：`_` 用不到為什麼還要寫型別？**
A：產生的程式碼一定會傳兩個參數進來，形狀由 `StrictServerInterface` 決定。`_` 只拿掉名字。

**Q：為什麼寫 `api.Ok`，不能寫 `"Ok"`？**
A：規格是小寫 `ok`，寫 `"Ok"` 本身就錯了。而且 Go 允許字串常數直接放進 `HealthStatus`，
所以 `"Ok"` **編譯得過**，只有測試會發現。`api.Ok` 打錯名稱、或規格改了 enum，都會在編譯時報錯。

**Q：`GetHealth200JSONResponse`、`GetHealthResponseObject` 從哪來？**
A：`make gen` 產生的。名稱 = operationId + 狀態碼 + 內容類型 + `Response`。
`GetHealthResponseObject` 是 interface，代表「這個 API 所有合法的回應」（菜單上的飲料類）。

**Q：`health_test.go` 在做什麼？**
A：像測自動販賣機：準備 handler → 呼叫 `GetHealth` → 檢查沒錯誤、型別是 200 回應、`Status` 是 `ok`。
不經過 HTTP，直接看回傳值。`main_test.go` 則是從 HTTP 測整間店。

**Q：`&` 是什麼？**
A：取地址，得到指標（給櫃子位置的紙條，而不是影本）。

## 遇到的錯誤

1. `cannot use api.GetHealthRequestObject{} ... as api.GetHealth200JSONResponse value in argument to h.GetHealth`
   - 原因：`health.go` 的第二個參數型別寫成 `api.GetHealth200JSONResponse`
   - 修正：改成 `api.GetHealthRequestObject`。錯誤報在呼叫端（測試），但問題在被呼叫的方法宣告
2. `go: cannot find main module`
   - 原因：`cd ..` 回到根目錄後跑 `go test`，根目錄沒有 `go.mod`
   - 修正：在根目錄用 `make test`，或在 `backend/` 裡跑 `go test ./...`

## 自我檢查

**1. 規格加上 `GET /api/version`（operationId `getVersion`）並跑 `make gen`，不寫 Go 程式碼，`go build` 會怎樣？**

失敗在 `cmd/api/main.go:24`：

```
*shared.HealthHandler does not implement api.StrictServerInterface (missing method GetVersion)
```

`make gen` 讓 `StrictServerInterface` 多了 `GetVersion` 方法（插座多了一個孔），
`HealthHandler` 沒有這個方法（插頭還是一隻腳）。跟路由無關，路由由 `HandlerFromMux` 自動註冊。
錯誤報在 `main.go` 而不是 `health.go`，因為隱式實作只在「交給要求介面的位置」時才檢查。
實驗時第一次忘了跑 `make gen`，`go build` 什麼都沒發現：編譯器只讀 `.go` 檔。

**2. 把 `api.Ok` 換成 `"Ok"`，`go build` 和 `make test` 會怎樣？**

- `go build` 成功（字串常數可以放進 `HealthStatus`）
- `health_test.go` 失敗：`got.Status != api.Ok`
- `main_test.go` 失敗：body 變成 `{"status":"Ok"}\n`，跟 `wantBody` 不相等
- 狀態碼那行**不會**失敗：`GetHealth200JSONResponse` 的 `VisitGetHealthResponse` 寫死 `WriteHeader(200)`

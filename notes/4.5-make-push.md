# Step 4.5：make push

## 目標與結果

`make push` 一次 build 並推送三個 amd64 image 到 Harbor：
`harbor.pf.internal/lab/esg-{backend,frontend,migrate}:<git short sha>`。
`docker buildx imagetools inspect` 看到三個 image 都是 `linux/amd64`，tag 為 `3944807`。

- `Makefile`：新增 `push`、`REGISTRY`、`TAG`、`PLATFORM`；工作區不乾淨時拒絕推送
- `backend/Dockerfile`：build 階段改 `--platform=$BUILDPLATFORM`，用 `GOOS/GOARCH` 交叉編譯
- `frontend/Dockerfile`：node 階段改 `--platform=$BUILDPLATFORM`
- 不需要 `imagePullSecret`：`harbor-pull` 已由平台的 ESO 產生（見 `docs/Platform.md`）

## 學到的概念

- **架構不同不能 retag**：Mac 是 arm64，k3s 是 amd64。compose build 出來的 image 是 arm64，所以 `make push` 要用 `docker buildx build --platform linux/amd64` 從原始碼重新 build。
- **`buildx`**：Docker 的進階 build 指令（BuildKit 引擎），支援 `--platform` 指定目標架構、`--push` 直接推到 registry、產生多架構 image index 與 attestation。
- **模擬 vs 交叉編譯**：不加 `--platform=$BUILDPLATFORM` 時，整個 build 階段在 QEMU 模擬的 amd64 下跑，很慢。加上之後 build 階段用原生 arm64 跑，Go 用 `GOARCH` 輸出 amd64 執行檔；runtime 階段沒加，所以最終 image 仍是 amd64。前端的 `dist/` 與架構無關，只需固定 build 階段的平台。
- **`ARG TARGETOS` / `TARGETARCH`**：BuildKit 會依 `--platform` 自動填值，但 Dockerfile 要用 `ARG` 宣告才讀得到。
- **tag 用 git short sha**：一個 tag 對應一個 commit，不用 `latest`。所以 `push` 先檢查 `git status --porcelain` 是否為空，避免 image 和 sha 對不上。
- **`unknown/unknown`**：`inspect` 會多出一筆，是 BuildKit 附加的 attestation manifest，不是第二個 image，不影響拉取。
- **Go 手動接線**：Spring 用 Jib / Maven 外掛包好 image；Go 要自己寫 Dockerfile 與 Makefile 的 push 流程。

```dockerfile
FROM --platform=$BUILDPLATFORM golang:1.26 AS build
ARG TARGETOS
ARG TARGETARCH
RUN CGO_ENABLED=0 GOOS=$TARGETOS GOARCH=$TARGETARCH go build -trimpath -ldflags="-s -w" -o /out/api ./cmd/api
```

## 問題與解答

- **那一行 `RUN CGO_ENABLED=0 GOOS=... go build ...` 是什麼意思？**
  `CGO_ENABLED=0` 產生靜態執行檔（distroless 沒有 libc）；`GOOS`/`GOARCH` 指定目標系統與 CPU；`-trimpath` 移除本機路徑；`-ldflags="-s -w"` 去掉符號表與除錯資訊以縮小檔案；`-o /out/api` 是輸出路徑；`./cmd/api` 是 `main` 所在的 package。開頭的 `A=1 command` 是 shell 語法，環境變數只對這一個指令有效。
- **什麼是 buildx？** 見上面「學到的概念」。類比：`docker build` 像 `javac`，`buildx` 像 Jib 加多平台設定。
- **這一步需要簽署與掃描嗎？** 不需要。掃描（Trivy）在 M11 的 CI 一次加入；簽署（cosign）ROADMAP 與 PRD 都沒有，平台也沒有 admission policy 驗證簽章。現況的保護是：sha tag 可追溯、Harbor project 私有、專用 push robot。
- **`make test` 出現 `No rule to make target`？** shell 停在 `backend/`，`Makefile` 在 repo 根目錄，回根目錄再跑。

## 自我檢查

**題目**：把 `FROM --platform=$BUILDPLATFORM golang:1.26` 改回 `FROM golang:1.26`，仍用 `buildx --platform linux/amd64` 在 Apple Silicon 上建置，會發生什麼事？

**答案**：輸出仍是 amd64（`GOARCH` 已指定），但整個 build 階段在 QEMU 模擬下執行，明顯變慢。

## 注意事項

- 推送前要先 `docker login harbor.pf.internal`（push robot，密碼從 Vault 經 stdin 讀）；robot 帳密不進 repo。
- `make push` 要在 commit 之後跑，sha 才會和程式碼一致；可用 `make push TAG=...` 覆寫 tag。
- 本步 image 的 sha 是 `3944807`；4.11 的 GitOps 會把這個 tag 寫進 platform-gitops 的 `values-dev.yaml`。

# Step 2.5：規格先行，POST /api/accounts

## 目標與結果
`api/openapi.yaml` 有 `POST /api/accounts`、`CreateAccountRequest`、`Account`、`FieldError`、`Error` 這幾個 schema。
`make gen` 重新產生後端 `api.gen.go` 和前端 `schema.d.ts`。後端的 `account.Handler.CreateAccount` 先回 501 stub。
`make test` 通過，後端覆蓋率 90.2%（門檻 80%）。對應 PRD 錯誤順序表第 7 項（422）。

## 學到的概念

**規格先行**：先改合約，再產生程式碼，最後實作。
Spring 對應 `openapi-generator` 產生 `XxxApi` interface，再由 `@RestController` 實作。
這裡的 `StrictServerInterface` 就是那個 interface：規格多一個 operation，interface 就多一個方法，沒實作就編譯不過。

**201 / 409 / 422**
| 碼 | 意義 | 本專案的情況 |
| --- | --- | --- |
| 201 | 建立成功 | 回傳 `Account` |
| 409 | 與現有資源衝突 | 工號已被註冊 |
| 422 | 格式正確但內容不合法 | 工號不是 6 碼數字 |

**統一錯誤格式 `Error`**：`code` 給程式判斷，`message` 給人看，`fields[]` 列出哪個欄位錯，`requestId` 對應 log。

**`oapi-codegen` 不驗證 schema 限制**：`pattern`、`minLength`、`maxLength` 只會出現在規格和前端型別，產生的後端程式碼只負責把 JSON 解碼進 struct。
Spring 的 `@Valid` 不會自動出現，422 的檢查要在 handler 手寫（Step 2.7）。
JSON 本身壞掉才會得到 400（`RequestErrorHandlerFunc`）。

**`default` response**：代表規格沒列出的其他狀態碼。產生的型別是 `CreateAccountdefaultJSONResponse`，帶 `StatusCode` 欄位。stub 借用它回 501，是暫時做法。

**為什麼是 501**：404 是路徑不存在，500 是伺服器出錯，501 是「這個 operation 還沒實作」，能讓呼叫者分辨「壞了」和「還沒做」。

**struct embedding 組合 handler**
```go
type server struct {
    *shared.HealthHandler
    *account.Handler
}
```
兩個 handler 的方法被提升成 `server` 的方法，所以 `server` 同時滿足整個 `StrictServerInterface`。
Spring 靠 component scan 自動收集所有 `@RestController`，Go 要在 `main.go` 手動組合。這是刻意的明確性，不是遺漏。

**型別斷言**：`resp.(api.CreateAccountdefaultJSONResponse)` 檢查 interface 背後的實際型別，對應 Java 的 `instanceof` 加轉型。`ok` 為 false 時不會 panic。

## 遇到的問題

**`go build` 說 no required module provides package `github.com/oapi-codegen/runtime`**
規格加了 `format: uuid` 和 `date-time` 之後，產生的程式碼用到 `types.UUID`，需要 `oapi-codegen` 的 runtime 套件。
修正：`go get github.com/oapi-codegen/runtime && go mod tidy`。Java 的類比是 `pom.xml` 少了產生程式碼要用的 library。

**`make: *** No rule to make target 'test'`**
上一個指令 `cd backend` 之後，shell 停在 `backend/`，那裡沒有 `Makefile`。回到 repo 根目錄再跑。

## 設計決定
PRD 沒寫密碼規則，這一步訂為長度 8–72。bcrypt 只看前 72 bytes，所以上限設 72。

## 自我檢查
1. 送 `{"employeeId":"abc","name":"x","password":"12345678"}` 給 stub 會回什麼？
   答：501。產生的程式碼只解碼 JSON，不驗證 `pattern`，`"abc"` 是合法的 JSON 字串，stub 照常執行。
2. 新增 operation 卻沒實作對應方法，哪一步會出錯？
   答：build time。`server` 不再滿足 `StrictServerInterface`，編譯就失敗，不會等到執行時才出現 404 或 501。
   Spring 的類比是 interface 多了抽象方法，沒實作的 class 編譯不過。

# 4.6 平台端：Vault role 與 MariaDB 帳號

## 目標與結果

讓 ESG 在 k3s 上能拿到機密、連上共用 MariaDB：

- Vault role `eso-esg` 從 `pull-only` 改成 `app` 類型，policy 變成 `k3s-app-esg`
- 密碼寫進 Vault `secret/k3s/esg/db`
- 在共用 MariaDB 建 database `esg` 與帳號 `esg`，驗收用 `esg` 帳號連進 `esg` database 成功

## 概念

### Vault role 是覆寫，不是新增

`k3s-jwt-auth.sh` 是冪等的。`app esg` 和先前的 `pull-only esg` 產生同名 role `eso-esg`，
所以重跑會把 role 指向新的 policy `k3s-app-esg`：

```text
path "secret/data/k3s/esg/*"     { capabilities = ["read"] }
path "secret/data/k3s/harbor-pull" { capabilities = ["read"] }
```

為什麼不用 `project` 類型：它只能讀 `secret/k3s/mariadb/apps/<name>`，讀不到 `harbor-pull`，
frontend 會拉不到 image。

### 密碼只存在 Vault 一份

`scripts/create-mariadb-esg.sh`（在 platform-gitops）從 Vault 讀帳密，再用 `kubectl exec` 進
`mariadb-0` 以 root 建帳號。密碼只經過 shell 變數和 pipe，不寫檔、不進 argv。

```sql
CREATE DATABASE IF NOT EXISTS `esg` CHARACTER SET utf8mb4;
CREATE USER IF NOT EXISTS 'esg'@'%' IDENTIFIED BY '...';
ALTER USER 'esg'@'%' IDENTIFIED BY '...';   -- 重跑時對齊 Vault
GRANT ALL PRIVILEGES ON `esg`.* TO 'esg'@'%';
```

Spring 對照：Spring Cloud Vault 會自動把機密注入設定；這裡 Vault 到 DB 的同步是腳本手動做的，
之後 Vault 到 Pod 由 ESO 做（4.7）。

## 連線資訊

| 項目 | 值 |
|---|---|
| Host（叢集內） | `mariadb.databases.svc.cluster.local` |
| Port | `3306` |
| Database | `esg` |
| User | `esg`（來源 `secret/k3s/esg/db` 的 `username`） |
| Password | 來源 `secret/k3s/esg/db` 的 `password` |
| 連線字串（migrate 用） | `mysql://<user>:<password>@tcp(mariadb.databases.svc.cluster.local:3306)/esg` |

這個位址只有叢集內的 Pod 連得到。Mac 若要連，要經 `scripts/mariadb-port-farwarding.sh` 或 `kubectl exec`。
密碼不寫進 Git：4.7 由 ESO 同步成 K8s Secret `esg-db`。

## 驗收

```bash
kubectl exec -i -n databases mariadb-0 -- env MYSQL_PWD="$PW" mariadb -uesg -D esg -e "SELECT DATABASE(), CURRENT_USER();"
```

輸出 `esg` 和 `esg@%`。

## 自我檢查

1. 只有 `CREATE USER IF NOT EXISTS`、沒有 `ALTER USER`，Vault 換密碼後重跑腳本會怎樣？
   答：DB 密碼仍是舊值。帳號已存在，CREATE 被略過，Vault 與 DB 不一致。
2. 為什麼 `esg` 帳號只授權 `esg`.*？
   答：共用 MariaDB 上，帳號被入侵時影響範圍限制在自己的 database，讀不到其他專案的資料。

## Pseudocode：一個請求的路線

```
瀏覽器（頁面來自 localhost:5173）
  App 第一次畫出來 → useEffect 呼叫 getHealth()
    fetch('/api/health')  → 只有路徑，送回頁面的來源 5173
      Vite proxy：/api 開頭 → 轉給 localhost:8080
        Go：RequestID → Logging → mux → HealthHandler → {"status":"ok"}
  res.ok？ 否 → throw → 畫面顯示 error
           是 → res.json() → 畫面顯示 ok
```

## 學到的概念

### 1. 同源政策（same-origin policy）

- 來源（origin）＝ **協定 + 主機 + port**，三樣都相同才算同源
- `localhost:5173` 和 `localhost:8080` 只差在 port，就已經是不同源
- 原因：同一台主機上，不同 port 可能是不同的程式和主人；瀏覽器看不出來，所以採取最保守的規則
- 跨源請求會被瀏覽器擋下，除非後端回應時明確放行（這就是 CORS）
- 網址省略 port 時代表預設值：`http` 是 80、`https` 是 443；`http` 和 `https` 也算不同源
- 正式網站幾乎只用 443，80 只負責轉址到 https

### 2. Vite dev proxy：開發時模擬同源

```ts
// frontend/vite.config.ts
server: { proxy: { '/api': 'http://localhost:8080' } }
```

- 瀏覽器只跟 5173 講話，由 Vite 在伺服器端轉給 8080 → 瀏覽器眼中是同源，不需要 CORS
- `client.ts` 用相對路徑 `/api/health`，前端不必知道後端在哪個 port
- 上線後由反向代理（reverse proxy）做同樣的事：`/api/*` 轉給 Go，其他路徑給 `dist/` 靜態檔

### 3. 502 Bad Gateway

中間那一站（Vite proxy）有收到請求，但連不上下一站（Go 後端）。意思是「後面的人不在」，不是前端程式有錯。

### 4. openapi-typescript：前後端的型別來自同一份 spec

```
api/openapi.yaml ──oapi-codegen──→ backend/internal/shared/api/api.gen.go
                 └─openapi-typescript─→ frontend/src/api/schema.d.ts
```

```ts
import type { components } from './schema'
export type Health = components['schemas']['Health']
```

- `make gen` 現在同時產生 Go 和 TS 的程式碼；改了 spec 就跑 `make gen`
- `import type`：只引入型別，編譯後完全消失，不會增加 bundle 的大小

### 5. `useState` + `useEffect` + 有區別的聯集（discriminated union）

```ts
type HealthState =
  | { kind: 'loading' }
  | { kind: 'ok'; status: string }
  | { kind: 'error'; message: string }
```

- 用 `kind` 區分三種狀態，TS 會依 `kind` 縮小型別：`kind === 'ok'` 時才拿得到 `status`
- 比用三個獨立的變數（`loading`、`data`、`error`）好：不可能同時是 loading 又是 error
- `useEffect(..., [])`：依賴陣列是空的 → 只在元件第一次掛上去時跑一次，**不會自動重試**，
  所以後端晚啟動時要手動重新整理
- `cancelled` 旗標加上 cleanup 函式：元件已經卸載時，就不再 `setHealth`

### 6. `fetch` 不會因為 4xx / 5xx 而丟錯

`fetch` 只有在網路層失敗時才會 reject。HTTP 錯誤要自己檢查 `res.ok`（狀態碼 200–299 時是 true），
所以 `client.ts` 才要寫 `if (!res.ok) throw ...`。

## 學習者的問題

1. **後端關著，畫面顯示 `502`，是錯了嗎？** 沒錯，這就是驗收要看的錯誤狀態。502 是 Vite proxy 連不上 8080。
   打開後端後要重新整理，因為 `useEffect` 只跑一次。
2. **`Unexpected token '<'` 是什麼？** `res.json()` 會對回應文字做 `JSON.parse`，但收到的是以 `<!doctype html>`
   開頭的 HTML，讀到第一個 `<` 就失敗。
   **實戰經驗**：看到這個錯誤，幾乎都代表「以為是 JSON，結果拿到 HTML」，通常是路徑打錯或 proxy 沒有生效。
3. **為什麼 Vite 找不到路徑時回 200 + `index.html`，而不是 404？** 這是 SPA fallback。
   像 `/submissions/123` 這種前端路由，伺服器上沒有對應的檔案，重新整理時必須回 `index.html`，
   React 才能啟動並依網址畫出畫面。副作用是打錯的 API 路徑也會拿到 200。
4. **為什麼不同 port 就算不同源？正式環境是不是用 80 + 443？** 見概念 1。

## 自我檢查

**Q1：刪掉 `vite.config.ts` 的 `proxy` 會怎樣？**
- `fetch('/api/health')` 打到 **5173**（頁面的來源），不是 8080。proxy 刪掉之後，就沒有人轉給後端了
- Vite 回 `index.html`，狀態碼 **200** → `res.ok` 是 **true** → 跳過 throw
- `res.json()` 解析 HTML 失敗 → 畫面顯示 `Backend: error Unexpected token '<', "<!doctype "... is not valid JSON`
- （一開始答成打到 8080、`res.ok` 是 false；後來發現和自己答出的錯誤訊息矛盾，因此更正）

**Q2：為什麼不直接 `fetch('http://localhost:8080/api/health')`？**
- 5173 → 8080 是跨源請求，瀏覽器會擋下，必須在後端加上 CORS 設定
- 違反專案不變量「前後端同源，不需要 CORS」
- 寫死 8080 也會讓前端綁定後端的位置；用相對路徑加上 proxy，前端不需要知道後端在哪裡

# 0.1 用 VitePress 把 notes/ 變成靜態網站

這是支線，不在 ROADMAP 裡。目標：不改動既有筆記，讓 `notes/` 直接變成可搜尋、有 sidebar 的小型文件網站。

## 完成的結果

- `notes/` 本身就是 VitePress 專案，沒有另外建 `docs-site/`。
- sidebar 由檔名自動產生，新增筆記不用改設定。
- `npm run dev` 在 `http://localhost:5173/` 預覽，`npm run build` 產生靜態網站。

## 工具比較與選擇

| | VitePress | Starlight | Docusaurus | MkDocs Material | mdBook |
|---|---|---|---|---|---|
| 技術棧 | Node + Vue | Node + Astro | Node + React | Python | Rust |
| 設定量 | 小 | 中 | 大 | 小 | 最小 |
| 對現有 md 的要求 | 無 | 每檔要有 frontmatter `title` | 無 | 無 | 要列在 `SUMMARY.md` |

選 VitePress 的理由：已經有 Node、筆記不用改、設定只有一個檔案。Starlight 要求每個檔案有 frontmatter，Docusaurus 太重，MkDocs 和 mdBook 要多裝一套語言工具。

## 檔案結構

```text
notes/
  package.json            # VitePress 依賴與 scripts
  index.md                # 網站首頁，不是步驟筆記
  .vitepress/config.mts   # 網站設定與 sidebar 產生邏輯
  0.1-... 1.2-... 2.4-... # 筆記本體
```

`notes/` 有 `package.json`，就像 Maven 專案有 `pom.xml`。`.vitepress/` 是 VitePress 的設定資料夾。

## 概念：用檔名產生 sidebar

```ts
const items = readdirSync(notesDir)
  .filter((f) => /^\d+\.\d+.*\.md$/.test(f))
  .sort((a, b) => a.localeCompare(b, 'en', { numeric: true }))
```

- `filter`：只收 `X.Y` 開頭的檔案，所以 `index.md` 不會進 sidebar。這也是筆記檔名必須維持 `X.Y-topic.md` 的原因。
- `numeric: true`：一般字串排序會把 `1.10` 排在 `1.2` 前面，因為字元 `1` 小於 `2`。啟用數字排序後，`1.9` 才會排在 `1.10` 前面，`1.6a` 也會排在 `1.6b` 前面。
- `new URL('..', import.meta.url)`：以設定檔位置為基準找 `notes/`，不受執行指令時所在目錄影響。

Spring 類比：這像是掃描 classpath 自動註冊元件，而不是手動列清單。

## 遇到的問題

### 1. npm 的 `allow-scripts` 警告

```text
npm warn allow-scripts 2 packages have install scripts not yet covered by allowScripts:
npm warn allow-scripts   esbuild@0.21.5
npm warn allow-scripts   fsevents@2.3.3
```

新版 npm 預設不執行套件的 install 腳本，因為這是供應鏈攻擊（supply chain attack）的常見入口。這只是警告，安裝已經完成。`esbuild` 的腳本只驗證二進位檔，`fsevents` 失敗時會退回 polling。只有 dev 或 build 真的報錯時，才需要執行 `npm approve-scripts <pkg>`。

### 2. build 出現 `Cannot read properties of undefined (reading 'Config')`

- 現象：`npm run build` 最後仍顯示 `build complete`，但 `2.1-compose-mariadb.md` 在 rendering 階段丟出 TypeError，這個頁面其實是壞的。
- 原因：VitePress 會把 Markdown 當 Vue 模板處理。筆記裡有行內程式碼包著 Go template 語法的雙大括號，Vue 把它當成插值（interpolation）去執行，結果找不到 `Config`。
- 重點：**程式碼區塊（fenced code block）會自動加 `v-pre`，行內程式碼不會。**
- 修正：用 `<span v-pre>` 把行內程式碼包起來，告訴 Vue 這段不要編譯。

```md
<span v-pre>`docker image inspect <image> --format '{{json .Config.Volumes}}'`</span>
```

- 另一個類似的坑：程式碼區塊外的 `<topic>` 會被當成 HTML 標籤，造成 `Element is missing end tag`。放進行內程式碼就安全。

> 教訓：`build complete` 不代表所有頁面都成功。要看 rendering 階段有沒有 error。

## 問題與解答

- **為什麼不另外建 `docs-site/`？** `srcDir` 要多指一層路徑，多一個資料夾也沒有好處。直接讓 `notes/` 成為 VitePress 專案更簡單。代價是 `notes/` 裡會有 `package.json` 和 `node_modules/`，但 `node_modules/` 已被 `.gitignore` 擋掉。
- **`build complete` 之後還有錯，要怎麼發現？** 看 `rendering pages...` 和 `build complete` 之間有沒有 error 輸出。

## 自我檢查

1. 如果把筆記改名成 `intro.md`，它會出現在 sidebar 嗎？
   不會。`filter` 的正規表示式要求 `X.Y` 開頭。頁面本身還是會被渲染，只是 sidebar 沒有連結。
2. 如果把 `numeric: true` 拿掉，`1.10` 會排在哪裡？
   會排在 `1.1x`、`1.2` 之前，因為逐字元比較時，字元 `1` 小於字元 `2`。

## 部署到 GitHub Pages

網站在 `https://esg.knowledge-forest.online/`。

### 流程

```text
push 到 main（改到 notes/**）
  -> Docs workflow：npm ci -> npm run build
  -> 上傳 notes/.vitepress/dist 當 Pages artifact
  -> deploy-pages 發佈
```

`.github/workflows/docs.yaml` 有兩個 job：

- `build`：安裝依賴、build、上傳 artifact。不需要 Pages 權限。
- `deploy`：用 `environment: github-pages` 發佈。需要 `pages: write` 和 `id-token: write`。

其他設定的理由：

- `paths: notes/**`：只有筆記或這個 workflow 變動才部署，改後端不會觸發。
- `workflow_dispatch`：可以在 Actions 頁籤手動重跑。
- `node-version: 24`：對齊 `mise.toml`。`notes/package.json` 沒有 `engines`，所以不能用 `node-version-file`。
- `concurrency`：同一時間只部署一次。

### GitHub 端設定

Settings → Pages → Build and deployment → Source 選 **GitHub Actions**，不選 branch。沒啟用之前，`gh api repos/<owner>/<repo>/pages` 會回 404，workflow 的 `configure-pages` 步驟會失敗。

### 自訂網域（Cloudflare）

1. Cloudflare 加一筆 CNAME：`esg` 指向 `brian-huanggg.github.io`，proxy 狀態選 **DNS only**（灰雲）。GitHub 需要直接連到網域才能簽發 HTTPS 憑證。
2. GitHub Settings → Pages → Custom domain 填入網域，等憑證簽發後勾選 **Enforce HTTPS**。
3. 用 Actions 部署時，不需要在 repo 放 `CNAME` 檔，設定頁面的值就是準的。

驗證：

```bash
dig +short esg.knowledge-forest.online CNAME
curl -I https://esg.knowledge-forest.online/
```

安全提醒：不用網域時要刪掉 CNAME，避免子網域被別人認領（subdomain takeover）。也建議在 GitHub 帳號做網域驗證（verified domain）。

### 遇到的問題：HTML 有了，但沒有 CSS

- 現象：部署成功，網站打得開，但只有純 HTML，沒有樣式。
- 診斷：看線上 HTML 的 stylesheet 路徑。

```bash
curl -s https://esg.knowledge-forest.online/ | grep -o '<link[^>]*stylesheet[^>]*>'
```

  結果是 `href="/esg/assets/style.xxxx.css"`，路徑多了 `/esg/` 前綴。
- 原因：`config.mts` 還留著 `base: '/esg/'`。這個值是給 `brian-huanggg.github.io/esg/` 用的，因為專案網站掛在 `/<repo>/` 底下。換成自訂網域後，網站在根路徑 `/`，前綴就變成錯的，CSS 和 JS 都 404。
- 修正：刪掉 `base`（預設就是 `/`）。部署完成後 `href` 變成 `/assets/style.xxxx.css`。

> 規則：`base` 要跟網站實際所在的路徑一致。`github.io/<repo>/` 用 `'/<repo>/'`，自訂網域用 `'/'`。

## 部署相關的自我檢查

1. 如果之後又想用回 `brian-huanggg.github.io/esg/`，要改什麼？
   把 `base` 改回 `'/esg/'`，並移除 GitHub 的自訂網域設定。
2. 為什麼 Cloudflare 的 CNAME 一開始要用灰雲？
   橘雲會讓流量先經過 Cloudflare，GitHub 驗證網域和簽發憑證時連不到自己的伺服器，可能失敗。

# Step 4.4：compose 全服務

## 目標與結果

`make compose-up` 一次起四個服務：`db` → `migrate` → `backend` → `frontend`。
用 Chrome 開 `http://localhost:8081`，註冊、登入、登出都成功（檢查點 1）。

- `deploy/compose.yaml` 新增 `migrate`、`backend`、`frontend`
- Makefile：`db-up` 只起 `db`；新增 `compose-up`；`db-down` 改名為 `compose-down`
- 驗證：`ps -a` 顯示 `migrate` 為 `Exited (0)`、其餘 Up；`curl localhost:8081/api/health` 回 200，且帶 `X-Request-Id`

## 學到的概念

- **服務名就是 DNS 名**：compose 為每個服務在內部網路建一筆同名 DNS 紀錄，所以 `DB_HOST=db`、`BACKEND_URL=http://backend:8080`。容器內的 `127.0.0.1` 是容器自己。
- **`depends_on` 的三種條件**：
  - `service_started`：容器啟動就算（預設）
  - `service_healthy`：healthcheck 通過才算（`migrate` 等 `db`）
  - `service_completed_successfully`：跑完且 exit 0 才算（`backend` 等 `migrate`）
- **一次性工作**：`migrate` 設 `restart: "no"`，跑完就結束。
- **同源**：`backend` 不發布 port，只有 Nginx 能連到它，瀏覽器只碰 Nginx，所以不需要 CORS。
- **compose 自己代入 `.env`**：`command` 是 exec 形式，容器不會展開環境變數，但 `${DB_USER}` 是 compose 讀 yaml 時就代入的。
- **Go 手動接線**：Spring 的 Flyway 在應用程式啟動時自己跑；Go 要在 yaml 裡明講啟動順序，且 `db.go` 要自己用 `os.Getenv` 讀設定。

```yaml
backend:
  environment:
    DB_HOST: db            # service name, not 127.0.0.1
  depends_on:
    migrate:
      condition: service_completed_successfully
```

## 問題與解答

- **為什麼 `DB_HOST` 是 `db`？** `db` 是 compose 的服務名，也是內部 DNS 名。本機 `make run-backend` 沒設 `DB_HOST`，走 `db.go` 的預設 `127.0.0.1`，連到發布出來的 3306。
- **之後的 DB 連線資訊是 Vault 或 Helm 注入嗎？** 兩者分工：非機密（`DB_HOST`、`DB_PORT`、`DB_NAME`）由 Helm 的 `values.yaml` 填進 Deployment；機密（`DB_USER`、`DB_PASSWORD`）由 Vault 經 VSO 同步成 K8s Secret，Deployment 用 `secretKeyRef` 讀。`db.go` 只讀環境變數，不知道值從哪來。
- **`depends_on` 是什麼？** 宣告啟動順序與條件；只管啟動時，不管之後 DB 中途掛掉，所以應用程式仍要處理連線失敗。
- **為什麼有 `compose-up` 沒有 `compose-down`？** `down` 不帶服務名，本來就停掉全部服務，`db-down` 名字誤導，所以改名為 `compose-down`，與 `compose-up` 成對。`down` 不刪 volume，`down -v` 才會。

## 注意事項

- cookie 設了 `Secure: true`。Chrome / Firefox 把 `http://localhost` 視為安全環境會接受，Safari 不會，驗收用 Chrome。
- 前端對外用 `127.0.0.1:8081`，因為 8080 留給本機 `run-backend`。
- `migrate` 顯示 `no change` 只代表 volume 已有資料；從空 DB 驗證要 `down -v` 後重跑。

## 自我檢查

1. backend 的 `depends_on.migrate.condition` 改成 `service_started` 會怎樣？—— backend 可能在 migration 還沒跑完時就啟動，因為 `service_started` 不等 migrate 跑完。
2. frontend 沒設 `BACKEND_URL`，沿用預設 `http://host.docker.internal:8080` 會怎樣？—— Nginx 把請求轉到主機的 8080，主機沒有服務就回 502。
